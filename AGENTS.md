# AGENTS.md

## Проект

Система мониторинга остатков, сроков годности и стоп-листов для ресторанов (кейс компании «Флагман»). Полное описание: [docs/Case.md](docs/Case.md).

Система рассчитана на несколько компаний и точек (ADR-013 в [docs/ADR.md](docs/ADR.md)): пользователь регистрируется и создаёт компанию, в ней точки; на каждой точке свой склад и своя кухня. Каталог (продукты, блюда, рецептуры) общий на компанию, всё остальное ведётся по точке. Владелец назначает на точку сотрудников с ролью: управляющий, приёмщик, повар, официант.

Основные возможности:
- приём поставок и учёт партий продуктов со сроками годности на точке;
- обработка заказов: проверка ингредиентов и списание по FEFO (сначала партии с самым ранним сроком);
- автоматический стоп-лист блюд точки при нехватке ингредиентов;
- мониторинг истекающих партий и рекомендации по поставкам;
- горячие предложения: блюда, продажу которых стоит стимулировать, с объяснением причины.

## Структура (монорепо)

- `frontend/` — веб-клиент. Свои правила: [frontend/AGENTS.md](frontend/AGENTS.md).
- `backend/` — серверная часть на Go. Свои правила: [backend/AGENTS.md](backend/AGENTS.md).
- `infra/` — инфраструктура: окружение разработки `infra/compose.yaml` (PostgreSQL, Kafka, Redis, Keycloak) и конфигурация его сервисов (запуск описан в [backend/AGENTS.md](backend/AGENTS.md)), а также запуск всей системы на сервере `infra/compose.prod.yaml` и выкладка: [infra/README.md](infra/README.md).
- `docs/` — описание кейса и проектная документация.
- `openspec/` — спецификации и изменения (spec-driven процесс через OpenSpec).
- `.agents/skills/` — общие скиллы для всего репозитория.

Работая над одной частью репо, запускай агента из её папки (например, из `frontend/`): так подхватываются её `AGENTS.md` и скиллы вместе с корневыми.

## Скиллы

- Источник скиллов — папка `.agents/skills/`: в корне для общих скиллов, в `frontend/`, `backend/`, `infra/` для скиллов своей части. Скиллы добавляются и редактируются только там.
- Рядом с каждой `.agents/skills/` лежит симлинк `.claude/skills` → `../.agents/skills`. Не заменяй его обычной папкой и не копируй скиллы в `.claude/` или другие каталоги агентов.
- Если инструменту нужен свой путь к скиллам, подключай его симлинком на `.agents/skills`, а не копией.
- Скилл кладётся в ту часть репо, к которой относится. В корне только то, что нужно всем (OpenSpec, git, общие правила).
- Имена скиллов частей репо начинаются с префикса части: `frontend-…`, `backend-…`, `infra-…`. Сторонние скиллы сохраняют своё имя.
- Каждый скилл — отдельная папка `<имя>/SKILL.md` с frontmatter (`name`, `description`).
- Если агент запущен из корня, а задача касается части репо, сначала прочитай `<часть>/AGENTS.md` и релевантные `<часть>/.agents/skills/*/SKILL.md`: из корня они могут не подгрузиться автоматически.

### Симлинк на Windows

Если клонировать репозиторий на Windows без включенных симлинков, `.claude/skills` будет обычным текстовым файлом, а не ссылкой, и Claude Code не увидит скиллы. Под Linux и macOS все работает сразу, под WSL - если и git, и агент запускаются внутри WSL.

Что нужно на Windows:

1. Включить режим разработчика (Параметры - Для разработчиков) либо запускать git от администратора.
2. Клонировать с включенными симлинками:

   ```bash
   git clone -c core.symlinks=true <url>
   ```

Если репозиторий уже клонирован и симлинки оказались файлами, пересоздай каждый (`.claude/skills`, `frontend/.claude/skills` и т.д.):

```bash
git config core.symlinks true
rm .claude/skills frontend/.claude/skills backend/.claude/skills
git checkout -- .claude/skills frontend/.claude/skills backend/.claude/skills
```

Проверка: `ls -la .claude/ frontend/.claude/ backend/.claude/` должен показать `skills -> ../.agents/skills`.

Не запускай `openspec init` и `openspec update` с `--tools claude`: они заменят симлинк обычной папкой. Используй `--tools codex`.
