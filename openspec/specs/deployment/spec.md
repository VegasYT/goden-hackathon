# deployment Specification

## Purpose
Развёртывание даёт работающую систему по публичной ссылке: вся система запускается на одном сервере одной командой, доступна только по HTTPS, а её секреты не лежат в репозитории.

## Requirements

### Requirement: Запуск системы на сервере одной командой
Репозиторий SHALL содержать описание, по которому одна команда `docker compose` на сервере с Docker собирает образы и запускает всю систему: PostgreSQL, Kafka, Keycloak, миграции, API, worker, генератор, frontend, обратный прокси, Prometheus, Loki, Promtail и Grafana. Миграции SHALL применяться до запуска API и worker. Версии сторонних образов SHALL быть закреплены.

#### Scenario: Первый запуск
- **WHEN** на сервере с заполненным `.env` выполняют команду запуска в свежем клоне репозитория
- **THEN** все сервисы запущены, API отвечает на проверку готовности, миграции применены

#### Scenario: Повторная выкладка
- **WHEN** после обновления кода команду запуска выполняют снова
- **THEN** пересобраны и перезапущены только изменившиеся сервисы, данные PostgreSQL и Kafka сохранены

#### Scenario: Перезагрузка сервера
- **WHEN** сервер перезагружается
- **THEN** система поднимается сама без ручных действий

### Requirement: Доступ по HTTPS
Система SHALL быть доступна только по HTTPS с действующим сертификатом, который получается и продлевается автоматически. Запрос по HTTP SHALL перенаправляться на HTTPS. Наружу SHALL быть открыты только порты 80 и 443: базы данных, Kafka, Prometheus, Loki, Promtail и служебные порты процессов SHALL NOT быть доступны из интернета.

#### Scenario: Адреса сервисов
- **WHEN** открывают `https://goden.pro`, `https://goden.pro/api/v1/me`, `https://goden.pro/docs`, `https://auth.goden.pro` и `https://grafana.goden.pro`
- **THEN** отвечают соответственно frontend, API (401 без токена), документация API, Keycloak и Grafana, у каждого действующий сертификат

#### Scenario: Запрос по HTTP
- **WHEN** открывают `http://goden.pro`
- **THEN** происходит перенаправление на `https://goden.pro`

#### Scenario: Закрытые порты
- **WHEN** с другой машины обращаются к портам PostgreSQL, Kafka, Prometheus, Loki, Promtail или к портам процессов backend на сервере
- **THEN** соединение не устанавливается

#### Scenario: Страница приложения по прямой ссылке
- **WHEN** открывают адрес страницы приложения, например `https://goden.pro/stock`, минуя главную
- **THEN** отвечает frontend, а не ошибка 404

### Requirement: Вход через Keycloak сервера
API на сервере SHALL проверять токены Keycloak, выпущенные по адресу `https://auth.goden.pro`. Режим без проверки токенов SHALL NOT использоваться.

#### Scenario: Запрос с токеном
- **WHEN** получают токен пользователя по адресу `https://auth.goden.pro` и обращаются с ним к API
- **THEN** API выполняет запрос в соответствии с правами пользователя

#### Scenario: Генератор
- **WHEN** генератор запущен на сервере и включён через API
- **THEN** он создаёт поставки и заказы под своей сервисной учётной записью

### Requirement: Секреты вне репозитория
Пароли и секреты сервера SHALL задаваться в файле `.env` на сервере, который не входит в репозиторий. Репозиторий SHALL содержать пример этого файла без действующих значений. Запуск без обязательного секрета SHALL завершаться понятной ошибкой, а не стартом со значением по умолчанию.

#### Scenario: Не задан секрет
- **WHEN** команду запуска выполняют без пароля администратора Keycloak в `.env`
- **THEN** запуск останавливается с сообщением, какой переменной не хватает

#### Scenario: Пароли разработки не действуют
- **WHEN** на сервере пробуют войти в консоль Keycloak как `admin` / `admin` или в приложение пользователем с паролем, равным логину
- **THEN** вход отклонён

### Requirement: Данные Keycloak сохраняются
Keycloak на сервере SHALL хранить данные в томе: пользователи, зарегистрировавшиеся самостоятельно, SHALL сохраняться при пересоздании контейнера и выкладке новой версии. Файл realm SHALL применяться только при первом создании данных.

#### Scenario: Выкладка новой версии
- **WHEN** пользователь зарегистрировался, после чего контейнер Keycloak пересоздали
- **THEN** пользователь входит с прежним паролем и видит свои компании

### Requirement: Демонстрационная компания на сервере
Запуск системы на сервере SHALL создавать демонстрационную компанию с тестовыми пользователями. Чат Telegram её первой точки SHALL задаваться настройкой окружения и может быть не задан.

#### Scenario: Запуск на пустом сервере
- **WHEN** систему запускают на сервере с пустыми данными
- **THEN** тестовый пользователь `admin` входит и видит компанию "Демо" с двумя точками

### Requirement: Сбой демонстрационной компании не останавливает запуск
Если демонстрационную компанию создать не удалось или её чат Telegram в настройке задан некорректно, запуск системы SHALL продолжаться: миграции считаются применёнными, API и worker запускаются, причина SHALL быть записана в журнал.

#### Scenario: Некорректный чат в настройке
- **WHEN** в настройке чата демонстрационной точки задано нечисловое значение и систему запускают
- **THEN** система запущена, в журнале миграций есть предупреждение

#### Scenario: Первая точка отключена
- **WHEN** владелец отключил первую точку демонстрационной компании и систему запускают снова
- **THEN** система запущена, новых событий нет

### Requirement: Настройки realm из окружения
При каждой выкладке на сервер система SHALL выставлять из настроек окружения срок access token, сроки сессии, русский язык форм Keycloak и подтверждение почты, не пересоздавая данные Keycloak: зарегистрированные пользователи SHALL сохраняться. Сбой этой настройки SHALL NOT останавливать запуск остальных сервисов и SHALL быть виден в журнале.

#### Scenario: Изменён срок сессии
- **WHEN** в настройках окружения меняют срок сессии и выкладывают версию
- **THEN** новые токены получают этот срок, пользователи, зарегистрировавшиеся раньше, входят с прежним паролем

#### Scenario: Пароль администратора не подходит
- **WHEN** пароль администратора Keycloak сменили в консоли, а в настройках окружения остался прежний
- **THEN** система запускается и работает, настройки realm не меняются, причина записана в журнале задачи настройки

#### Scenario: Формы на русском
- **WHEN** пользователь открывает страницу входа или регистрации
- **THEN** она на русском языке

### Requirement: Подтверждение почты при регистрации
Подтверждение почты SHALL включаться и выключаться настройкой окружения и по умолчанию быть выключенным. При включённом подтверждении зарегистрировавшийся пользователь SHALL получать письмо со ссылкой и входить только после перехода по ней. Без настроенного почтового сервера подтверждение SHALL NOT включаться. Тестовые пользователи SHALL входить независимо от настройки.

#### Scenario: Включено
- **WHEN** подтверждение включено и человек регистрируется
- **THEN** ему уходит письмо на русском со ссылкой, до перехода по ней в приложение он не попадает

#### Scenario: Выключено
- **WHEN** подтверждение выключено и человек регистрируется
- **THEN** он сразу попадает в приложение

#### Scenario: Нет почтового сервера
- **WHEN** подтверждение включают, не задав почтовый сервер
- **THEN** подтверждение остаётся выключенным, причина записана в журнале задачи настройки

#### Scenario: Тестовый пользователь
- **WHEN** подтверждение включено и входит тестовый пользователь
- **THEN** он попадает в приложение без письма

### Requirement: Тема страниц входа на сервере
Keycloak на сервере SHALL отдавать страницы входа темы `goden`. Тема SHALL собираться из кода репозитория при выкладке и включаться в realm при каждой выкладке, не пересоздавая данные Keycloak: зарегистрированные пользователи SHALL сохраняться. Изменение страниц темы SHALL доходить до сервера обычной выкладкой.

#### Scenario: Выкладка на сервер с пользователями
- **WHEN** на сервере, где пользователи уже зарегистрировались со стандартными страницами Keycloak, выкладывают версию с темой
- **THEN** страница входа открывается в оформлении Goden, а пользователи входят с прежними паролями

#### Scenario: Изменение страницы
- **WHEN** в коде меняют страницу входа и выкладывают версию
- **THEN** на сервере страница входа показывает изменение

#### Scenario: Запуск на пустом сервере
- **WHEN** систему запускают на сервере с пустыми данными
- **THEN** страница входа сразу открывается в оформлении Goden

### Requirement: Клиенты Мигома на сервере
При каждой выкладке система SHALL заводить в Keycloak сервера клиентов сервиса доставки Мигом, которых там нет, с их ролями, не пересоздавая данные Keycloak. Секреты клиентов Мигома SHALL браться из настроек окружения при каждой выкладке. Если секрет не задан, клиент SHALL NOT принимать секрет из файла realm.

#### Scenario: Клиентов нет
- **WHEN** на сервере с зарегистрированными пользователями выкладывают версию с заданными секретами Мигома
- **THEN** сервисная учётная запись Мигома получает токен с ролью `migom.integration` по секрету из настроек, пользователи сохранились

#### Scenario: Секрет сменили
- **WHEN** секрет Мигома в настройках окружения меняют и выкладывают версию
- **THEN** токен выдаётся по новому секрету, по старому - нет

#### Scenario: Секрет не задан
- **WHEN** секрет Мигома не задан
- **THEN** токен по секрету разработки из файла realm не выдаётся

### Requirement: Мигом за прокси сервера
Прокси сервера SHALL открывать адреса сервиса доставки Мигом, который работает на том же сервере в общей сети: API Мигома и его фото на основном домене Мигома, кабинет владельца на `owner.` и кабинет модератора на `admin.` этого домена, с сертификатами Let's Encrypt. Пока Мигом не запущен, Goden SHALL работать как прежде.

#### Scenario: Кабинет владельца
- **WHEN** пользователь открывает `https://owner.migom.site`, а Мигом запущен
- **THEN** открывается кабинет владельца Мигома по HTTPS

#### Scenario: Мигом не запущен
- **WHEN** Мигом на сервере не запущен
- **THEN** адреса Мигома отвечают 502, адреса Goden работают

### Requirement: Очередь выкладок на сервере
Выкладка Goden SHALL ждать окончания выкладки Мигома на том же сервере и наоборот.

#### Scenario: Две выкладки сразу
- **WHEN** выкладка Мигома идёт, а начинается выкладка Goden
- **THEN** выкладка Goden начинает сборку только после окончания выкладки Мигома
