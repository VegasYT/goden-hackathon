## ADDED Requirements

### Requirement: Статус остатка продукта
Система SHALL определять статусы остатка продукта на точке на момент запроса:

- `in_stock` - доступное количество больше нуля;
- `expiring` - ближайший срок годности среди непросроченных партий с остатком наступает не позже чем через сутки;
- `expired` - просроченное количество больше нуля;
- `out_of_stock` - доступное количество равно нулю.

Статусы SHALL NOT исключать друг друга: продукт с годной и просроченной партией имеет и `in_stock`, и `expired`.

#### Scenario: Годная партия со сроком через неделю
- **WHEN** у продукта одна годная партия со сроком через неделю
- **THEN** у него только статус `in_stock`

#### Scenario: Срок в пределах суток
- **WHEN** ближайший срок годной партии продукта наступает через 20 часов
- **THEN** у продукта статусы `in_stock` и `expiring`

#### Scenario: Граница суток
- **WHEN** ближайший срок годной партии наступает ровно через 24 часа
- **THEN** у продукта есть статус `expiring`

#### Scenario: Годная и просроченная партии
- **WHEN** у продукта одна партия просрочена, а другая годна
- **THEN** у продукта статусы `in_stock` и `expired`

#### Scenario: Только просроченная партия
- **WHEN** у продукта единственная партия с остатком просрочена
- **THEN** у продукта статусы `expired` и `out_of_stock`

#### Scenario: Продукт без партий
- **WHEN** у продукта нет партий с остатком
- **THEN** у него только статус `out_of_stock`

### Requirement: Фильтры и сортировка остатков
Чтение остатков точки SHALL принимать необязательные параметры: `q` - начало названия продукта без учёта регистра, `category` - точное значение категории, `status` - один статус остатка, `sort` - порядок. Общее число SHALL считаться после фильтров. Без параметров ответ SHALL совпадать с прежним: все продукты каталога по названию.

Параметр `sort` SHALL принимать `name`, `nearest_expiry`, `available` и те же значения с минусом для обратного порядка; по умолчанию `name`. При сортировке по сроку продукты без ближайшего срока SHALL идти последними в обоих направлениях. Продукты с равным значением SHALL идти по названию. Неизвестное значение `status` или `sort` SHALL отклоняться со статусом 400.

#### Scenario: Поиск по началу названия
- **WHEN** в каталоге "Сливки 33%", "Сливочное масло" и "Соль" и запрашивают остатки с `q=слив`
- **THEN** возвращаются "Сливки 33%" и "Сливочное масло", общее число равно двум

#### Scenario: Знак шаблона в поиске
- **WHEN** запрашивают остатки с `q=%`
- **THEN** возвращаются только продукты, название которых начинается со знака `%`

#### Scenario: Категория
- **WHEN** запрашивают остатки с категорией, в которой один продукт
- **THEN** возвращается этот продукт

#### Scenario: Категория без продуктов
- **WHEN** запрашивают остатки с категорией, которой нет в каталоге
- **THEN** возвращается пустой список и общее число ноль

#### Scenario: Фильтр по статусу
- **WHEN** запрашивают остатки со статусом `expired`
- **THEN** возвращаются только продукты с просроченным количеством

#### Scenario: Пагинация после фильтра
- **WHEN** под фильтр подходят три продукта и запрашивают страницу размером два со смещением два
- **THEN** возвращается третий продукт, общее число равно трём

#### Scenario: Сортировка по доступному количеству
- **WHEN** запрашивают остатки с `sort=-available`
- **THEN** продукты идут от большего доступного количества к меньшему

#### Scenario: Сортировка по сроку
- **WHEN** запрашивают остатки с `sort=nearest_expiry`
- **THEN** продукты идут от ближайшего срока к дальнему, продукты без годных партий - в конце

#### Scenario: Неизвестная сортировка
- **WHEN** запрашивают остатки с `sort=price`
- **THEN** возвращается статус 400

### Requirement: Сводка остатков по статусам
Система SHALL отдавать через `GET /api/v1/points/{pointId}/stock/summary` число продуктов каталога компании точки: общее и по каждому статусу остатка. Сводка SHALL учитывать параметры `q` и `category` так же, как чтение остатков, и не принимать `status`. Числа SHALL считаться на момент запроса по синхронной таблице партий. Операция SHALL требовать право `inventory.view`.

#### Scenario: Числа по статусам
- **WHEN** в каталоге три продукта: с годной партией, с годной и просроченной партиями, без партий
- **THEN** сводка показывает всего 3, `in_stock` 2, `expired` 1, `out_of_stock` 1, `expiring` 0

#### Scenario: Сводка с поиском
- **WHEN** запрашивают сводку с `q`, под который подходит один продукт
- **THEN** общее число равно одному, числа по статусам посчитаны только по нему

#### Scenario: Пустой каталог
- **WHEN** в каталоге компании нет продуктов
- **THEN** все числа сводки равны нулю

#### Scenario: Нет права
- **WHEN** сводку запрашивает сотрудник без права `inventory.view`
- **THEN** возвращается статус 403
