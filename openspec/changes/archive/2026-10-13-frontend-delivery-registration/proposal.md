## Why

Поставку на точке сейчас можно зарегистрировать только через API или кнопкой «Привезти поставку» в разделе «Генератор», а она собирает случайные позиции и видна одному владельцу. Управляющему по кейсу нужно вносить реальную поставку по накладной поставщика («Получение новой поставки», docs/Case.md, раздел 1), чтобы приёмщик её проверил. Право `deliveries.register` у управляющего и владельца уже есть, API готово (`POST /points/{pointId}/deliveries`).

## What Changes

- В шапке списка поставок появляется кнопка «Новая поставка». Её видят только пользователи с правом `deliveries.register` на точке.
- Форма «Новая поставка» по адресу `/points/{pointId}/deliveries/new`:
  - номер поставки;
  - дата и время поступления, по умолчанию текущие;
  - позиции: продукт из каталога компании с поиском, количество в единице продукта (кг, л, шт), «Годен до» (дата и время), необязательная дата изготовления;
  - позиции можно добавлять и удалять.
- Проверки до отправки: обязательные поля, положительное количество, дробные штуки. Изготовлено не позже срока годности, срок годности не дольше срока хранения продукта.
- Если срок позиции уже истёк, показывается предупреждение, но регистрация разрешена.
- Ошибки сервера показываются у полей позиций, сбой связи — текстом с повтором, который не создаёт вторую поставку.
- После регистрации открывается карточка поставки с формой приёмки, поставка появляется в списке.
- При уходе со страницы с заполненной формой задаётся вопрос.
- Вне изменения:
  - сканирование и загрузка накладной файлом;
  - создание продукта прямо из формы: каталог ведёт владелец, это отдельный раздел;
  - выбор поставщика (в API его нет);
  - редактирование и удаление зарегистрированной поставки (в API нет).

### Modified Capabilities

## Impact

- `frontend/`:
  - новая страница `pages/delivery-new` и роут `points.$pointId.deliveries.new`;
  - кнопка в `pages/deliveries`;
  - запрос каталога переезжает из `pages/generator` в новую сущность `entities/product`, потому что у него появляется второй потребитель;
  - регистрация поставки переезжает из `pages/generator` в `entities/delivery`, её используют обе страницы.
- Новые зависимости frontend: `@mui/x-date-pickers` 9.x и `date-fns` 4, обёртки полей с провайдером дат в `shared/ui/date-field`, стили поля пикера — в теме.
- Контракт API и backend не меняются.
- Пересечение с изменением `frontend-delivery-after-approval` (worktree `frontend/delivery-acceptance-2`): обе ветки правят шапку списка поставок и `entities/delivery`. Сливать вторую ветку нужно после первой.
