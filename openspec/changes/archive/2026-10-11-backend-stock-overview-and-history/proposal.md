# Proposal

## Why

Главного экрана склада у системы нет: партии читаются только по одному продукту, а сводки "что и сколько есть, что просрочено, что скоро истечёт" по всему складу нет. Нельзя и посмотреть, что происходило: как менялась приёмка поставки после решения по карантину и корректировок и почему изменился остаток продукта. Все эти данные уже лежат в системе - в таблице партий и в потоках событий, - их нужно только отдать. Это вторая часть задачи B2 из [backend/plan.md](../../../backend/plan.md); разработчик B задерживается, задачу выполняет разработчик A.

## What Changes

- `GET /api/v1/stock` - остатки по складу: по строке на продукт каталога с доступным количеством, просроченным количеством, числом партий и ближайшим сроком годности. Постранично, по названию продукта.
- `GET /api/v1/deliveries/{deliveryId}/history` - история поставки: по записи на каждое событие потока поставки с временем, автором и состоянием поставки после события. По ней восстанавливается весь ход приёмки: исходное распределение, решения по карантину, корректировки.
- `GET /api/v1/products/{productId}/movements` - движения по продукту: получение партий, расход по заказам, списания, корректировки и предупреждения о сроке, от последних к ранним, постранично.

Проекции не нужны: остатки читаются из синхронной таблицы партий и потому не отстают от записи, истории - прямо из потоков событий.

Вне изменения: фильтры остатков по категории и по состоянию; сводные числа по складу в целом; экран истекающих партий с настраиваемым периодом (задача B4); стоп-лист (B3).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `stock`: остатки по складу, движения по продукту.
- `deliveries`: история поставки.
- `event-store`: чтение потока от последних событий к ранним порциями.

## Impact

- **Код:** `internal/inventory` (запрос остатков, сервис, обработчики), `internal/platform/eventstore` (чтение потока в обратном порядке), `internal/platform/command` (доступ к часам для чтения), `api/openapi.yaml` и перегенерированный `oas`, матрица прав в тестах.
- **Права:** остатки и движения - `inventory.view`, история поставки - `deliveries.view`.
- **Frontend:** получает данные для главного экрана склада, карточки поставки и карточки продукта.
- **Документы:** `backend/AGENTS.md`, `backend/plan.md` (B2 закрыта, выполнил разработчик A).
