# Spec Delta

## Purpose

Как веб-клиент Goden обращается к API: по какому адресу, с каким токеном и как сообщает пользователю об ошибках запросов. Правила общие для всех экранов.

## ADDED Requirements

### Requirement: Адрес API
Веб-клиент SHALL обращаться к API по относительному адресу `/api/v1` на том же домене, с которого открыто приложение.

#### Scenario: Приложение на стенде
- **WHEN** приложение открыто по адресу `https://goden.example/`
- **THEN** запросы к API уходят на `https://goden.example/api/v1/...`

### Requirement: Авторизация запросов
Каждый запрос к API SHALL отправляться с действующим access token вошедшего пользователя в заголовке `Authorization: Bearer`. Если срок токена истекает, токен SHALL обновляться до отправки запроса. Запрос без токена SHALL NOT отправляться.

#### Scenario: Токен скоро истекает
- **WHEN** экран делает запрос, а токену осталось жить несколько секунд
- **THEN** запрос уходит с новым токеном, и API не отвечает 401

### Requirement: Отказ API в аутентификации
Ответ API со статусом 401 SHALL показываться пользователю как обычная ошибка запроса с текстом из ответа. Приложение SHALL NOT отправлять пользователя на вход из-за ответа API: на вход ведёт только отказ Keycloak продлить сессию.

#### Scenario: API не принял действующий токен
- **WHEN** у пользователя действующая сессия, а API отвечает на запрос статусом 401
- **THEN** пользователь видит текст ошибки из ответа и остаётся на текущем экране

### Requirement: Тексты ошибок
Ошибку запроса SHALL показывать пользователю текстом из ответа сервера в формате `application/problem+json`: поле `detail`, а если его нет, поле `title`. Сообщения об ошибках отдельных полей SHALL браться из `errors[].message` ответа. Свой текст клиент SHALL показывать только тогда, когда текста от сервера нет:

| Случай | Текст |
| --- | --- |
| ответ не получен | Нет связи с сервером. Проверьте подключение и повторите |
| ответ получен не в формате `problem+json` | Сервер вернул неожиданный ответ. Повторите позже |

#### Scenario: Нет права на действие
- **WHEN** API отвечает на запрос статусом 403 с `detail` «Для этого действия нужно право inventory.edit»
- **THEN** пользователь видит «Для этого действия нужно право inventory.edit»

#### Scenario: Ошибка без пояснения
- **WHEN** API отвечает ошибкой в формате `problem+json` без поля `detail`
- **THEN** пользователь видит текст из поля `title`

#### Scenario: Сервер не ответил
- **WHEN** запрос не получил ответа из-за обрыва сети
- **THEN** пользователь видит «Нет связи с сервером. Проверьте подключение и повторите»

#### Scenario: Ответ не в формате ошибок API
- **WHEN** вместо API ответил прокси со статусом 502 и HTML-страницей
- **THEN** пользователь видит «Сервер вернул неожиданный ответ. Повторите позже»
