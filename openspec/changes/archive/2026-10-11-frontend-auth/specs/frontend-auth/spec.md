# Spec Delta

## Purpose

Вход пользователя веб-клиента Goden через Keycloak, его сессия и права. Права определяют, какие разделы доступны, а сессия держится, пока пользователь работает.

## ADDED Requirements

### Requirement: Вход через Keycloak
Приложение SHALL работать только для вошедшего пользователя. Без сессии пользователь SHALL попадать на страницу входа Keycloak, а после входа возвращаться на тот адрес приложения, который открывал. Пароль SHALL вводиться только на странице Keycloak, не в приложении.

#### Scenario: Первое открытие
- **WHEN** пользователь без сессии открывает адрес раздела «Поставки»
- **THEN** открывается страница входа Keycloak, а после входа пользователь видит раздел «Поставки»

### Requirement: Восстановление входа
Если в браузере есть действующая сессия Keycloak, приложение SHALL открываться без ввода пароля, в том числе после перезагрузки страницы и в новой вкладке. Если сессии Keycloak нет или она истекла, пользователь SHALL попадать на страницу входа.

#### Scenario: Перезагрузка страницы
- **WHEN** вошедший пользователь перезагружает страницу раздела «Кухня»
- **THEN** снова открывается раздел «Кухня», пароль не запрашивается

#### Scenario: Сессия Keycloak истекла
- **WHEN** пользователь открывает приложение после того, как его сессия Keycloak истекла
- **THEN** открывается страница входа Keycloak

### Requirement: Хранение сессии
Токены пользователя SHALL храниться только в памяти открытой вкладки. Приложение SHALL NOT сохранять их в `localStorage`, `sessionStorage`, cookie или другом хранилище браузера.

#### Scenario: Хранилища браузера после входа
- **WHEN** пользователь вошёл и работает в приложении
- **THEN** в хранилищах браузера для адреса приложения нет токенов Keycloak

### Requirement: Продление сессии
Пока сессия Keycloak действует, работа SHALL продолжаться без повторного входа, сколько бы ни длилась. Если сессию продлить нельзя, пользователь SHALL попадать на страницу входа, а после входа возвращаться на тот же адрес.

#### Scenario: Долгая работа
- **WHEN** пользователь работает в приложении дольше срока действия одного токена, но сессия Keycloak действует
- **THEN** пароль повторно не запрашивается

#### Scenario: Сессию продлить нельзя
- **WHEN** приложение пытается продлить сессию пользователя, а Keycloak отказывает
- **THEN** открывается страница входа, а после входа пользователь возвращается на тот же адрес

#### Scenario: Сессию завершили в Keycloak
- **WHEN** администратор завершил сессию пользователя в Keycloak, а пользователь продолжает работать
- **THEN** не позже чем через срок жизни токена, при следующем запросе, открывается страница входа

### Requirement: Права пользователя
Права пользователя SHALL браться из его токена: роли клиента `goden-api`. Права SHALL определять, какие разделы доступны. «Сводка» SHALL быть доступна любому вошедшему пользователю. Остальные разделы требуют права:

| Раздел | Право |
| --- | --- |
| Склад | `inventory.view` |
| Поставки | `deliveries.view` |
| Заказы | `orders.view` |
| Кухня | `kitchen.view` |
| Стоп-лист | `kitchen.view` |
| Аналитика | `analytics.view` |

#### Scenario: Повар
- **WHEN** входит пользователь с ролью повара (права `kitchen.view`, `catalog.view`)
- **THEN** ему доступны «Сводка», «Кухня» и «Стоп-лист», остальные разделы недоступны

#### Scenario: Менеджер
- **WHEN** входит пользователь с ролью менеджера
- **THEN** ему доступны все разделы

### Requirement: Раздел без права
Прямой адрес раздела, на который у пользователя нет права, SHALL открывать внутри оболочки страницу «Нет доступа к разделу» с названием раздела и ссылкой на «Сводку». Данные раздела при этом SHALL NOT запрашиваться.

#### Scenario: Повар открывает склад по адресу
- **WHEN** пользователь с ролью повара открывает адрес раздела «Склад»
- **THEN** в оболочке показывается страница «Нет доступа к разделу» со ссылкой на «Сводку»

### Requirement: Пользователь без прав
Пользователь, у которого в токене нет ни одного права клиента `goden-api`, SHALL видеть страницу «Нет доступа к приложению» с действием «Выйти» вместо оболочки с разделами.

#### Scenario: Пользователь без ролей
- **WHEN** входит пользователь Keycloak без единой роли приложения
- **THEN** показывается «Нет доступа к приложению» и кнопка «Выйти», навигации по разделам нет

#### Scenario: Выход со страницы без прав
- **WHEN** такой пользователь нажимает «Выйти»
- **THEN** сессия Keycloak завершается и открывается страница входа

### Requirement: Текущий пользователь и выход
Оболочка SHALL показывать профиль вошедшего пользователя: инициалы, имя из профиля Keycloak (без имени — логин) и роль по-русски, если у пользователя есть одна из ролей приложения. В узкой панели имя и роль SHALL быть доступны в меню профиля. Действие «Выйти» SHALL находиться в меню профиля, завершать сессию Keycloak, а не только вкладки, и возвращать пользователя на страницу входа.

#### Scenario: Профиль в боковой панели
- **WHEN** входит пользователь `manager` с именем «Менеджер Тестовый»
- **THEN** в боковой панели показаны инициалы «МТ», имя «Менеджер Тестовый» и роль «Менеджер»

#### Scenario: Профиль в узкой панели
- **WHEN** пользователь на планшете нажимает кнопку профиля с инициалами
- **THEN** открывается меню с его именем, ролью, переключением темы и действием «Выйти»

#### Scenario: Выход
- **WHEN** пользователь выбирает «Выйти» в меню профиля, а затем снова открывает приложение
- **THEN** открывается страница входа Keycloak и запрашивается пароль

### Requirement: Сервер входа недоступен
Если при открытии приложения Keycloak не отвечает или вход не завершился за 15 секунд, приложение SHALL показывать сообщение, что не удалось связаться с сервером входа, и действие «Повторить». Бесконечной загрузки SHALL NOT быть. Повтор после восстановления Keycloak SHALL продолжать обычный вход.

#### Scenario: Keycloak остановлен
- **WHEN** пользователь открывает приложение, а Keycloak не отвечает
- **THEN** показывается сообщение о недоступности сервера входа и кнопка «Повторить»

#### Scenario: Keycloak отвечает ошибкой
- **WHEN** Keycloak отвечает, но вместо завершения входа отдаёт страницу ошибки
- **THEN** не позже чем через 15 секунд показывается сообщение о недоступности сервера входа и кнопка «Повторить»

#### Scenario: Повтор после восстановления
- **WHEN** Keycloak снова доступен и пользователь нажимает «Повторить»
- **THEN** приложение продолжает вход как при обычном открытии
