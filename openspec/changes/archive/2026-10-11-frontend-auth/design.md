# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/frontend-auth`, `specs/frontend-api` и `specs/frontend-shell`.

**Что уже есть:**
- В `infra/keycloak/goden-realm.json` есть realm `goden` и публичный клиент `goden-web`. У клиента PKCE S256, адреса возврата и выхода `http://localhost:5173/*`, web origin `http://localhost:5173`. Маппер аудитории добавляет `goden-api` в access token.
- Права пользователя приходят через составные роли в `resource_access.goden-api.roles`. Тестовые пользователи: `admin`, `manager`, `approver`, `cook`, `waiter`, пароль совпадает с логином.
- API проверяет токен и право каждой операции. Право записано в контракте: `security: bearerAuth: [право]`. Ошибки приходят в `application/problem+json`: `type`, `title`, `status`, `detail`, `correlation_id`, `errors`. `title` и `detail` бэкенд сейчас пишет на английском (`internal/api/errors.go`) и переводит их на русский отдельной правкой.
- Во `frontend/`:
  - роутер создаётся при импорте `src/app/router.tsx`, в контексте только `queryClient`;
  - роуты разделов — заглушки `SectionStubPage`;
  - навигация задана в `src/app/layouts/app-shell/nav-items.ts`;
  - `axios` установлен, но не используется;
  - в `.env.example` лежит неиспользуемый `VITE_API_URL`.
- Приложение и Keycloak на стенде будут на одном домене. Локально `localhost:5173` и `localhost:8180` браузер считает одним сайтом.

## Goals / Non-Goals

**Goals:**
- Экраны получают вошедшего пользователя и его права синхронно. Отдельных состояний «сессия загружается» нет: сессия поднимается до рендера.
- Один клиент API, и у каждого запроса токен уже есть. Экран не думает о токене.
- Экраны показывают ошибку одним вызовом и не разбирают формат ответа сами.

**Non-Goals:**
- Экраны и функции запросов к данным разделов.
- Своя форма входа. Пароль вводится только на странице Keycloak.
- Синхронизация выхода между вкладками.

## Decisions

### 1. keycloak-js, сессия в памяти, тихая проверка через iframe

Решено с пользователем. Сравнивали с `oidc-client-ts` + `react-oidc-context`. Для выбранной схемы keycloak-js проще:
- тихая проверка входа через статичную `public/silent-check-sso.html`;
- переход на обычный редирект встроен, если cookie недоступны (`silentCheckSsoFallback`);
- разбор кода после возврата из Keycloak делает `init()`;
- `tokenParsed` с `resource_access`.

У oidc-client-ts преимущества другие: хранение в `sessionStorage` и привязки к React. Ни то ни другое при сессии в памяти не нужно.

Настройки `init()`:
- `onLoad: 'check-sso'`;
- `silentCheckSsoRedirectUri: <origin>/silent-check-sso.html`;
- `checkLoginIframe: false`: фоновая проверка выхода в других вкладках не нужна, а это лишний iframe и запросы;
- `pkceMethod: 'S256'` — значение по умолчанию, указываем явно.

Если `init()` вернул «не вошёл», вызываем `keycloak.login()`. Адрес возврата по умолчанию текущий, поэтому пользователь вернётся туда же.

Токены keycloak-js держит в памяти. Во время редиректа он ненадолго кладёт в `localStorage` служебные данные входа (state и PKCE verifier) и удаляет их после возврата. Токенов там нет, требование «Хранение сессии» это не нарушает.

### 2. Запуск приложения: сначала сессия, потом роутер

```
  main.tsx
    render(<StartupScreen/>)                  фон темы; лого и индикатор через 400 мс
    startSession()
      |-- ошибка init (Keycloak не ответил) -> <AuthUnavailablePage/>
      |                                        "Повторить" = перезагрузка страницы
      |-- не вошёл -> keycloak.login()       уход на Keycloak, рендера дальше нет
      |-- вошёл, прав goden-api нет -> <NoAccessPage/> с "Выйти"
      '-- вошёл -> createAppRouter({ queryClient, session })
                   render(<SessionProvider session><RouterProvider/></SessionProvider>)
```

- **Роутер создаётся после `init()` фабрикой `createAppRouter`.** После возврата из Keycloak keycloak-js убирает код авторизации из адреса через `history.replaceState`. Роутер, созданный раньше, запомнил бы адрес с кодом. Тип для `Register` берётся из `ReturnType<typeof createAppRouter>`.
- **«Повторить» на странице ошибки перезагружает страницу.** `init()` у одного экземпляра keycloak-js вызывается только один раз.
- **Экран загрузки показывает индикатор с задержкой 400 мс.** При обычном старте (iframe, примерно 100–300 мс) виден только фон, а если Keycloak не отвечает, видно, что приложение ждёт. Без ответа Keycloak `init()` падает по таймауту ожидания iframe проверки cookie (`messageReceiveTimeout`, по умолчанию 10 с). Значение не меняем.
- **`startSession` ограничивает `init()` 15 секундами.** Тихая проверка входа в keycloak-js 26 (`#checkSsoSilently`) ждёт сообщения от iframe без таймаута. Если Keycloak отвечает страницей ошибки, а не переходом на `silent-check-sso.html`, `init()` не завершается никогда. По истечении 15 с — `<AuthUnavailablePage/>`. Срок больше 10 с, чтобы штатный таймаут keycloak-js срабатывал первым.

### 3а. Профиль в оболочке

По макету «Goden — макеты интерфейса» (артборды LaptopDark и TabletDark):
- **Боковая панель, низ.** Строка связи, если источник подключён. Под линией кнопка профиля: аватар 32 px с инициалами на `primary.tint`, имя (`text.strong`), роль (`text.tertiary`). Справа переключатель темы.
- **Узкая панель, низ.** Точка связи и круглая кнопка профиля 44 px с инициалами.
- **Меню профиля.** Заголовок с именем и ролью, в узкой панели ещё переключение темы, «Выйти».
- **Роль.** Берётся из `realm_access.roles` токена по порядку: `admin` «Администратор», `manager` «Менеджер», `approver` «Приёмщик», `cook` «Повар», `waiter` «Официант». Других ролей нет, поэтому и строки роли нет. Роль только подпись, права по-прежнему из `resource_access.goden-api`.
- **Переключение темы.** Логика переключателя выносится в хук `useModeSwitch` в `shared/ui/theme`. Его используют `ModeToggle` и пункт меню.

### 3. Раскладка по FSD

```
src/shared/config/                env.ts (адрес Keycloak, realm, клиент: из VITE_* или значения для localhost),
                                  vite-env.d.ts (типы VITE_*), index.ts
src/shared/auth/                  keycloak.ts (экземпляр), start-session.ts, session.ts (тип Session,
                                  sessionFromToken, can), permissions.ts (список прав ADR-006),
                                  session-context.ts (контекст, useSession), session-provider.tsx
                                  (SessionProvider), token.ts (getAccessToken, relogin, logout), index.ts
src/shared/api/                   client.ts (axios), api-error.ts (ApiError, toApiError),
                                  schema.gen.ts (сгенерирован), index.ts
src/shared/ui/standalone-screen/  экран без оболочки: запуск, нет доступа, ошибка входа
src/pages/forbidden/              "Нет доступа к разделу"
src/pages/no-access/              "Нет доступа к приложению"
src/pages/auth-unavailable/       "Не удалось связаться с сервером входа"
src/app/                          main.tsx (запуск), startup-screen.tsx (экран загрузки),
                                  router.tsx (createAppRouter, appRouterDefaults),
                                  app-error-component.tsx (ForbiddenPage по ForbiddenError),
                                  section-access.ts (ForbiddenError, requireSection), routes (проверка прав),
                                  layouts/app-shell (навигация по правам, блок пользователя)
```

Сессия и токен лежат в `shared/auth`. Так рекомендует FSD-скилл для токенов и их обновления: это инфраструктура, а не сущность. `shared/api` берёт токен из `shared/auth`, импорт между сегментами `shared` разрешён. Отдельный `features/logout` не нужен: выход — один вызов из оболочки и со страницы без прав.

### 4. Права и разделы

- `Permission` — объединение строк из ADR-006. `sessionFromToken` берёт роли из `resource_access['goden-api'].roles` и оставляет только известные права.
- Имя для оболочки берётся из `name` токена, без него — из `preferred_username`.
- Право раздела записано в `nav-items.ts` полем `permission?: Permission`. У «Сводки» его нет. Отсюда его берут навигация (фильтр `can`) и проверка роутов, так что источник один.
- Каждый роут раздела в `beforeLoad` вызывает `requireSection(context.session, '/stock')`, который бросает `ForbiddenError`. `defaultErrorComponent` роутера рисует `ForbiddenPage` с названием раздела. Ошибка из `beforeLoad` дочернего роута должна показываться в `Outlet` корня, поэтому оболочка остаётся. Это гипотеза о границах ошибок по совпадениям роутов, документация прямо этого не говорит. Её проверяет тест приложения. Если не подтвердится, `beforeLoad` вместо исключения вернёт в контекст признак запрета, а компонент роута по нему покажет `ForbiddenPage`. Остальные ошибки отдаются стандартному компоненту ошибки TanStack Router.
- `beforeLoad` идёт раньше загрузчиков роута, поэтому данные раздела без права не запрашиваются.

### 5. Клиент API

- `axios.create({ baseURL: '/api/v1' })`.
- Перехватчик запроса берёт токен у `getAccessToken()` из `shared/auth` и ставит `Authorization: Bearer`. `getAccessToken` вызывает `keycloak.updateToken(30)`, одновременные вызовы keycloak-js сводит в одно обновление.
- Если `updateToken` не удался, `getAccessToken` различает два случая по `keycloak.refreshToken`. keycloak-js стирает его, только когда Keycloak отказал продлить сессию (ответ 400). При отказе вызывается вход, один на все одновременные запросы, и запрос ждёт ухода страницы. При обрыве связи или ответе 5xx токен остаётся, запрос завершается ошибкой «Нет связи с сервером…», на вход приложение не уводит.
- Отменённый запрос отклоняется отменой axios, а не `ApiError`.
- На вход ведёт только отказ Keycloak продлить сессию. Ответ API 401 становится обычной `ApiError`. API проверяет токен сам, по ключам Keycloak, без запроса в Keycloak (`go-oidc`, `internal/platform/auth/auth.go`). Поэтому завершённую сессию API замечает не раньше, чем истечёт токен, а к этому моменту продление уже отправит на вход. 401 на действующий токен означает ошибку настройки API: издатель, аудитория, расхождение часов. Повторный вход её не исправит и только зациклит переходы между приложением и Keycloak. Вариант «уводить на вход по 401 и защищаться от цикла меткой времени» отвергнут как лишний механизм.
- Типы ответов берутся из `schema.gen.ts`, а функции запросов будут писаться в слоях экранов (`components['schemas']`, `paths`). Генерировать клиент не стали: решено с пользователем, сгенерированный код хуже ложится на FSD.

### 6. Ошибки для пользователя

`toApiError` собирает `ApiError` из ошибки axios: `status`, `type`, `message`, `fieldErrors` и `correlationId`. В `message` попадает `detail`, иначе `title` из `problem+json`. Если ответа нет или он не в формате API, туда попадает один из двух текстов клиента из спеки. Экран показывает `message`, а сообщения полей берёт из `fieldErrors`.

Своих текстов по видам ошибок клиент не держит, это решение пользователя: тексты задаёт бэкенд, и он переводит их на русский. Пока перевода нет, пользователь увидит английский текст. Это осознанный временный компромисс, а не причина заводить таблицу переводов на фронте.

### 7. Типы контракта

- `pnpm api:types` = `openapi-typescript ../backend/api/openapi.yaml -o src/shared/api/schema.gen.ts`.
- Файл коммитится и исключается из ESLint, Prettier и Steiger, как `routeTree.gen.ts`.
- Проверено в scratchpad: openapi-typescript 7.13 генерирует файл с нашим TypeScript 6.0.3 (в peer-зависимостях у него `^5.x`), и файл проходит `tsc --strict` с нашими флагами.

### 8. Окружение и прокси

- В `vite.config.ts` добавлено `server.proxy['/api'] → http://localhost:8080`: в dev запросы идут на тот же адрес, что и на стенде, и CORS не участвует. Цель прокси можно переопределить `API_PROXY_TARGET`.
- `VITE_KEYCLOAK_URL`, `VITE_KEYCLOAK_REALM` и `VITE_KEYCLOAK_CLIENT_ID` имеют значения по умолчанию для локального стенда: `http://localhost:8180`, `goden`, `goden-web`. Поэтому `pnpm dev` работает без `.env`.
- Неиспользуемый `VITE_API_URL` из `.env.example` убирается.

### 9. Тесты

По `frontend-testing` проверяем только нашу логику, keycloak-js не тестируем:
- `sessionFromToken`: права из `resource_access`, отбрасывание неизвестных ролей, имя с запасным логином;
- `startSession` с подставным объектом Keycloak: вошёл, не вошёл (вызван `login`), ошибка `init`;
- `startSession` без единого права приложения возвращает «нет доступа»;
- `getAccessToken` с подменённым keycloak: отказ Keycloak уводит на вход с возвратом на текущий адрес, одновременные отказы уводят один раз, обрыв связи на вход не уводит;
- клиент API с подменённым адаптером axios:
  - заголовок `Bearer` с токеном из `getAccessToken`;
  - без токена запрос не отправляется и даёт «Нет связи с сервером…»;
  - 401 отдаётся как `ApiError` с текстом из ответа;
  - отменённый запрос отклоняется отменой, а не ошибкой связи;
- `toApiError`: текст из `detail`, запасной `title`, ошибки полей, два случая без ответа API;
- приложение через `renderApp` с сессией повара:
  - в навигации три пункта;
  - адрес «Склада» показывает «Нет доступа к разделу» в оболочке;
  - блок пользователя с именем, «Выйти» вызывает выход;
- `NoAccessPage`: «Выйти» вызывает выход.

`renderApp` получает параметр `session`. По умолчанию это сессия со всеми правами, поэтому существующие тесты роутов и оболочки не меняются.

## Risks / Trade-offs

- **[Тихая проверка зависит от cookie Keycloak в iframe]** → На одном домене cookie первые. Если домены всё же разойдутся, keycloak-js сам перейдёт на обычный редирект, просто вход при перезагрузке станет заметным.
- **[Клиент `goden-web` разрешает возврат только на `http://localhost:5173/*`]** → `pnpm dev` должен работать на порту 5173 (он по умолчанию), а `vite preview` (4173) для входа не подойдёт. Адреса стенда добавит бэкенд в realm вместе с деплоем.
- **[Keycloak не отвечает — ошибка только через 10 с]** → Экран загрузки показывает индикатор. Таймаут не сокращаем: на медленной сети планшета короткий таймаут давал бы ложную ошибку.
- **[Простой дольше срока сессии Keycloak (30 мин по умолчанию)]** → Первый запрос после простоя отправит на вход, и несохранённые данные формы потеряются. Срок сессии оставили по умолчанию, это решение пользователя.
- **[Права в токене обновляются только при новом токене]** → Если роль сменили во время работы, навигация обновится не раньше перезагрузки. Доступ всё равно проверяет бэкенд (ADR-006).
