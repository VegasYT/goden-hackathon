## Why

Бэкенд принимает запросы к `/api/v1` только с токеном Keycloak и проверяет право на каждую операцию (спека `authorization`). У фронтенда пока нет ни входа, ни клиента API. Без них нельзя начать ни один экран, а разделы у ролей разные: повару нужны кухня и стоп-лист, официанту — заказы, приёмщику — поставки. Вход, права и общий клиент API нужны раньше экранов, чтобы не встраивать их потом в каждый экран.

## What Changes

- Вход через страницу Keycloak (realm `goden`, клиент `goden-web`, PKCE). Сессия хранится только в памяти вкладки. При открытии приложения вход восстанавливается без перехода страницы, если в браузере есть сессия Keycloak, иначе пользователь уходит на страницу входа.
- Токен обновляется перед запросами. Если Keycloak отказался продлить сессию, пользователь заново проходит вход. Ответ API 401 показывается как обычная ошибка и на вход не уводит.
- Права пользователя берутся из токена. Навигация показывает только разделы, на которые у пользователя есть право. «Сводка» доступна любому вошедшему.
- Прямой адрес раздела без права открывает в оболочке страницу «Нет доступа к разделу». Пользователь без единого права приложения видит «Нет доступа к приложению» и может выйти.
- В оболочке показываются имя пользователя и кнопка «Выйти».
- Если сервер входа недоступен, приложение показывает сообщение и действие «Повторить».
- Общий клиент API: относительный адрес `/api/v1`, токен в каждом запросе, типы запросов и ответов из `backend/api/openapi.yaml`. Текст ошибки для пользователя берётся из ответа `problem+json`. Свой текст клиент показывает только при обрыве связи или ответе не в формате API.
- В `pnpm dev` запросы к `/api` проксируются на API (`localhost:8080`).

Вне изменения:
- русская локаль страницы входа Keycloak — правка realm в `infra`, её делает бэкенд;
- экраны разделов и запросы к их данным;
- виджеты «Сводки» по правам — вместе с экраном сводки;
- скрытие кнопок действий по правам внутри экранов — вместе с каждым экраном;
- SSE и состояние связи;
- срок сессии Keycloak (остаётся по умолчанию);
- режим работы фронтенда без Keycloak.

## Capabilities

### New Capabilities
- `frontend-auth`: вход через Keycloak, сессия пользователя, права из токена, доступ к разделам, выход.
- `frontend-api`: обращение веб-клиента к API: адрес, авторизация запросов, тексты ошибок для пользователя.

### Modified Capabilities
- `frontend-shell`: навигация показывает только разделы, доступные пользователю.

## Impact

- `frontend/`:
  - новые зависимости `keycloak-js` и `openapi-typescript` (dev);
  - новые модули `shared/auth` и `shared/api` со сгенерированными типами контракта;
  - запуск приложения в `src/app/main.tsx`, контекст роутера, защита роутов разделов;
  - оболочка: навигация по правам, блок пользователя;
  - страницы «Нет доступа к разделу», «Нет доступа к приложению» и ошибки входа;
  - `public/silent-check-sso.html`, прокси `/api` в `vite.config.ts`, переменные окружения Keycloak;
  - команда генерации типов API, раздел в `frontend/AGENTS.md`.
- `backend/` и `infra/` в этом изменении не меняются. Тексты ошибок API сейчас на английском, бэкенд переводит их на русский отдельной правкой. До неё пользователь увидит английский текст.
- Используются уже настроенные клиент `goden-web` (PKCE, адреса `http://localhost:5173/*`) и контракт `backend/api/openapi.yaml`.
- Для ручной проверки нужны поднятый Keycloak из `infra/compose.yaml` и API с `OIDC_ISSUER`. Фронтенд должен работать на `localhost:5173`: только этот адрес разрешён клиенту `goden-web`.
