# Proposal

## Why

Поставки, склад и заказы реализованы и проверены, но снаружи недоступны: через API сейчас можно только заполнить каталог. Нельзя принять поставку, оформить заказ или списать испорченное, поэтому не работают ни ручная проверка главных сценариев кейса, ни frontend, ни генератор (A6), который по ADR-012 ходит только через публичный API. Это задачи A3.2, A4.1 и A5.1 из [backend/plan.md](../../../backend/plan.md).

Три задачи объединены в одно изменение: это одна и та же механическая работа - операции контракта и тонкие обработчики поверх готовых команд, без новых правил. Раздельно они дали бы три одинаковых круга с одним и тем же файлом контракта.

## What Changes

- **Поставки (A3.2):** регистрация поставки, чтение поставки, приёмка, решение по карантину позиции, корректировка приёмки.
- **Склад (A5.1):** партии продукта в порядке FEFO, партия по идентификатору, ручное списание, корректировка остатка.
- **Заказы (A4.1):** оформление заказа и чтение заказа.
- Модули `inventory` и `orders` получают HTTP-обработчики; `internal/api` собирает их вместе с каталогом.
- Отказ в заказе из-за нехватки продуктов возвращается успешным ответом с заказом в статусе "отклонён" и списком нехваток: это результат, записанный событием, а не ошибка запроса.
- Правила предметной области и общие правила API не меняются.
- В `backend/plan.md` задачи A3.2, A4.1, A5.1 отмечаются выполненными.

Вне изменения: списки поставок и заказов, остатки по складу в целом, стоп-лист, истекающие партии - это проекции и эндпоинты чтения разработчика B; команды для worker (списание просрочки, предупреждение о сроке) через API не публикуются; авторизация (A7).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `deliveries`: добавляется требование доступности операций с поставками через HTTP API.
- `stock`: добавляется требование доступности партий, списания и корректировки через HTTP API.
- `orders`: добавляется требование доступности оформления и чтения заказа через HTTP API.

## Impact

- **Код:** `backend/api/openapi.yaml`, перегенерированный `backend/internal/api/oas`; новые `backend/internal/inventory/http.go` и `backend/internal/orders/http.go`; `backend/internal/api/api.go` - сборка трёх модулей.
- **Документы:** `backend/plan.md` - статусы A3.2, A4.1, A5.1.
- **Разработчик B:** в контракте появляются разделы `deliveries`, `stock`, `orders` с операциями записи. Его эндпоинты чтения добавляются в те же разделы или в свои; владение по тегам из `plan.md` сохраняется.
- **Frontend:** получает эндпоинты для экранов приёмки поставки, складского учёта (списание, корректировка) и оформления заказа.
- **Генератор (A6):** разблокируется.
