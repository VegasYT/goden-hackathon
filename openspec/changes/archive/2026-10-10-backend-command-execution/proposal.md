# Proposal

## Why

Event Store умеет добавлять события в поток, но всё, что делает команду корректной по ADR-002, пока пришлось бы повторять в каждом доменном модуле: блокировки по продуктам в едином порядке, запись в несколько потоков одной транзакцией, защита от повторной обработки, повтор при конфликте версий, заполнение служебных полей события. Каталог, поставки, заказы и списания (задачи A2-A5) должны опираться на одну проверенную реализацию, а не писать её четыре раза. Это задача A1 из [backend/plan.md](../../../backend/plan.md).

## What Changes

- Появляется пакет `internal/platform/command` с единой точкой выполнения команды. Доменный код передаёт описание команды и функцию с бизнес-логикой, всё остальное делает платформа.
- Команда выполняется в одной транзакции PostgreSQL: события всех потоков и связанные таблицы фиксируются вместе или не фиксируются вовсе.
- Перед первой записью команда берёт advisory-блокировки на заявленные потоки в едином порядке. Команды с общим потоком выстраиваются в очередь, команды без общих потоков идут параллельно.
- Команда с ключом идемпотентности выполняется один раз: повторный вызов с тем же ключом возвращает сохранённый результат и не создаёт событий. Тот же ключ с другим содержимым запроса отклоняется.
- При конфликте версий потока или взаимной блокировке команда повторяется целиком ограниченное число раз, затем возвращает ошибку.
- Служебные поля события заполняются единообразно: идентификатор, время из `clock.Clock`, correlation ID из контекста, идентификатор команды как causation ID, автор и имя команды в метаданных.
- Появляется миграция таблицы результатов команд для идемпотентности.
- `backend/AGENTS.md` дополняется правилом: доменные команды запускаются только через этот пакет.

Вне изменения: сами доменные команды и агрегаты, синхронные таблицы каталога и остатков, HTTP-эндпоинты и чтение заголовка с ключом идемпотентности (A2-A5), метрики конфликтов и повторов (A8), очистка старых записей идемпотентности.

## Capabilities

### New Capabilities

- `command-execution`: выполнение команд записи - атомарность, блокировки по потокам, идемпотентность по ключу запроса, повтор при конфликте, единое заполнение служебных полей событий.

### Modified Capabilities

Нет. Требования `event-store`, `domain-events` и `backend-platform` не меняются: новая возможность использует их как есть.

## Impact

- **Код:** новый пакет `backend/internal/platform/command/`, новая миграция в `backend/migrations/`. Существующие пакеты не меняются.
- **Зависимости:** новых нет.
- **Документы:** `backend/AGENTS.md` - описание пакета и правило для доменных команд. `docs/ADR.md` не меняется: изменение реализует раздел "Команды, затрагивающие несколько потоков" из ADR-002.
- **Разработчик B:** не затрагивается. Его проекции читают те же события; в метаданных событий появляются автор и имя команды, которыми он может пользоваться. Автосписание и предупреждение о сроке (B4) будут вызывать команды A5, построенные на этом пакете.
- **Frontend и infra:** не затрагиваются.
