## Goals / Non-Goals

**Goals:**
- Вкладки без дублирования диалогов, уведомления и панели истории между «Остатками» и «Сроками».

**Non-Goals:**
- Перенос запросов склада в `entities`: второго потребителя вне склада пока нет (сводка появится позже).

## Decisions

### Вкладки — дочерние роуты склада

```
points.$pointId.stock.tsx          layout: шапка, вкладки, панель истории; search { history }
  points.$pointId.stock.index.tsx    «Остатки»: q, category, status, sort, page, size
  points.$pointId.stock.expiring.tsx «Сроки»: within (24 | 72 | 168, по умолчанию 72), page, size
  points.$pointId.stock.reorder.tsx  «Пора заказать»: page, size; beforeLoad проверяет recommendations.view
```

Свой адрес у вкладки даёт ссылку и «Назад» без ручной синхронизации; у каждой вкладки своя схема адреса, параметры «Остатков» не мешают «Срокам». `history` объявлен в layout, поэтому дочерние роуты его наследуют, а ссылка стоп-листа `/points/$pointId/stock?history=…` продолжает открывать «Остатки» с панелью. Альтернатива — параметр `?tab=` на одном роуте — смешала бы схемы трёх вкладок в одну.

Проверка права вкладки — `requirePermission(queryClient, pointId, permission, section)` рядом с `requireSection` в `app/point-access.ts`: бросает тот же `ForbiddenError`, страница «Нет доступа к разделу» уже есть. Вкладки — MUI `Tabs` со ссылками роутера (`TabLink` в `shared/ui/link`, как `ButtonLink`); на планшете `variant='fullWidth'`, высота 44.

### Запросы новых вкладок

- `stockKeys.expiring(pointId, params)` → `['points', pointId, 'stock', 'expiring', params]`: `GET /batches/expiring` с `within_hours`, `limit`, `offset`.
- `recommendationKeys.deliveries(pointId, params)` → `['points', pointId, 'recommendations', 'deliveries', params]`: `GET /recommendations/deliveries`. Параметры расчёта клиент передаёт явно (24, 24, 72), чтобы строка параметров на экране не расходилась с расчётом, если на сервере поменяют значения по умолчанию.
- Свежесть — `pointDataFreshMs`, `placeholderData` — `keepPointData`, как у остатков. Ключи под `['points', pointId, …]`, поэтому поток событий точки сможет пометить их устаревшими по категориям `expiry`, `stock` и `recommendations`.
- Число на «Сроках» — `total` запроса `within_hours=24, limit=1`; на «Пора заказать» — `total` того же запроса, что первая страница вкладки по умолчанию, поэтому при открытой первой странице отдельного запроса нет. Без права `recommendations.view` запрос рекомендаций выключен (`enabled`).
- `storeBatch` дополнительно перечитывает `['points', pointId, 'stock', 'expiring']` и `['points', pointId, 'recommendations']`: списание меняет и то, и другое.

### Общие для вкладок действия с партией

Диалоги списания и исправления, уведомление «Списано…» с действием «История» выносятся из `StockPage` в компонент `BatchActionDialogs` в `pages/stock/ui` (имя `BatchActions` уже занято кнопками партии); его используют «Остатки» и «Сроки», «История» в уведомлении меняет `history` в адресе layout. Диалоги и `ProductLine` принимают `Product` вместо `StockLevel`: доступное количество считается чистой функцией `productStock(batches, now)` (сумма годных партий с остатком и их число) по живым партиям, которые диалог уже читает. Та же функция даёт `HistoryPanel` строку «доступно · N партий», и панель перестаёт зависеть от страницы остатков, поэтому живёт в layout и открывается с любой вкладки. Цена — запрос партий продукта при открытии истории со «Сроков» или «Пора заказать»; с «Остатков» партии раскрытого продукта уже в кэше.

### Строки и форматы

- «Сроки», статус — `ExpiryLabel lead='remaining' withDate={false}` (дата в своей колонке); у просроченной — `expiredLabel='просрочена'`, `expiredNote='спишется автоматически'`, ячейка действия пустая. На планшете — `inline` с датой.
- «Хватит на» — `cover_hours` целыми часами вниз («9 ч»), меньше часа — «меньше часа», всегда предупреждением: сервер рекомендует только запас меньше суток. Без `cover_hours` (не было расхода) и при нуле доступного — «—».
- Блюда — первые два через запятую и «и ещё N» с `Tooltip` полным списком; элемент «и ещё N» фокусируемый, чтобы подсказка открывалась и с клавиатуры.
- «Как считаем» — кнопка с `aria-expanded` и `Collapse`, состояние локальное, в адрес не пишется.
- Название продукта на «Сроках», «Пора заказать» и в стоп-листе — `TextLink color='inherit' underline='hover'`: выглядит как текст, подчёркивается при наведении. Решение пользователя по макетам.

## Risks / Trade-offs

- [Число на «Сроках» считает сутки, а вкладка по умолчанию показывает 3 дня: «Сроки 4» и 7 партий в списке] → так в согласованном макете: число — срочные партии, список — горизонт планирования.
- [Без таймера список «Сроков», открытый надолго, не добирает партии, которые вошли в период, пока он открыт] → оставшееся время и «просрочена» обновляются раз в минуту (`useNow`), состав перечитывается при возврате на вкладку и после списания; дальше — поток событий точки.
- [Существующие тесты склада получают новые запросы чисел вкладок] → `stockApi` в `app/test-stock.ts` отвечает на них пустыми страницами по умолчанию.
