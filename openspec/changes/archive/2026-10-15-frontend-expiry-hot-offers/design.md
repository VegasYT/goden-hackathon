# Design

## Context

- **Контракт уже в `develop`.**
  - Движение `expired`: изменение остатка в нём нулевое, как у `expiry_warning`.
  - У `DishRecommendation` появилось необязательное `manual` (`comment`, `set_by`, `set_at`); `reasons` у закреплённого блюда может быть пустым.
  - Новые операции:
    - `GET /points/{pointId}/recommendations/dishes/settings` — `HotOfferSettings`: закреплённые и скрытые сегодня блюда;
    - `PUT /points/{pointId}/recommendations/dishes/{dishId}` — `HotOfferChange` (`mode`, `comment`, `time_zone`), ответ `HotOfferSetting`.
  - Изменения настроек приходят сигналом `recommendations`.
- **Склад сейчас:**
  - просроченная партия без действий: `batch-list.tsx`, `expiring-page.tsx`;
  - `writableBatches` в `model/actions.ts` не даёт выбрать просроченную партию;
  - подписи «спишется автоматически» — в `stock-rows.tsx`, `batch-list.tsx`, `BatchExpiryLabel`, «спишется сама» — в `dashboard/model/tiles.ts`.
- **Горячие предложения** читаются через `hotDishesQueryOptions` под `hotDishKeys.all(pointId)`. Этот префикс уже перечитывает сигнал `recommendations`.
- Макеты — страница холста «Изменения API: просрочка и горячие предложения».

## Goals / Non-Goals

**Goals:**
- фронт перестаёт обещать автоматическое списание;
- просрочку можно списать в два нажатия;
- управляющий закрепляет и скрывает предложения на вкладке «Горячие предложения».

**Non-Goals:**
- массовое списание;
- отдельный экран настроек предложений;
- закрепление из «Кухни» или «Стоп-листа».

## Decisions

1. **Типы.** `pnpm api:types`. Новое значение `expired` в таблицах подписей движений: TypeScript покажет все места, где `Record` по виду движения неполный.
2. **Списание просроченной партии.**
   - Просроченная партия попадает в выбор партии диалога списания. Исправление остатка её по-прежнему не предлагает: такого требования нет.
   - Если диалог открыт для просроченной партии, начальные значения — причина `expired` и весь остаток.
   - Модель `writeOffProblems` не требует комментарий для причины `expired`. Пустой комментарий уходит пустой строкой: поле в API обязательное, но длина не ограничена снизу.
3. **Плашка над «Сроками».** Число берётся из `GET /stock/summary` (`expired` — продукты с просроченным остатком). Тот же запрос без фильтров уже есть у склада, поэтому плашка правдива при любой странице и периоде. Партии на странице для этого не считаются: просрочка может уйти на следующие страницы.
4. **Подписи.** `BatchExpiryLabel` и строки склада получают `expiredNote='нужно списать'`. Подпись счётчика сводки — «просрочена, нужно списать». Кнопка «Списать» у просроченной партии — `color='error'` с заливкой, у годной — прежняя.
5. **Горячие предложения: данные.**
   - В `entities/dish`:
     - `hotOfferSettingsQueryOptions(pointId)` под `hotDishKeys.all(pointId)`, поэтому его перечитывает тот же сигнал `recommendations` без новой строки в `point-signals.ts`;
     - запись `setHotOffer(pointId, dishId, change, idempotencyKey)`.
   - Хук записи в `pages/orders` после ответа помечает устаревшим весь `hotDishKeys.all(pointId)`: от режима зависит порядок списка.
6. **Часовой пояс скрытия** — `Intl.DateTimeFormat().resolvedOptions().timeZone` браузера. Решение выведено из контракта: другого источника пояса у фронта нет.
7. **Отмена.** Сообщение после действия возвращает прежний режим той же записью:
   - отмена закрепления — `auto`;
   - отмена скрытия — `auto`;
   - отмена снятия — `pinned` с прежним комментарием.
8. **«Добавить блюдо».**
   - Варианты — меню точки (`menuQueryOptions`, оно уже в кэше у «Кухни» и нового заказа) без уже закреплённых блюд, `Autocomplete` по названию.
   - Блюдо из стоп-листа выбрать можно. Сервер сохранит закрепление и покажет блюдо, когда его можно будет приготовить. Под полем — пояснение об этом.
9. **Где управлять.** Действия только на вкладке «Горячие предложения», право — `writeAccess(profile, point, 'menu.manage')`. Новый заказ и «Сводка» лишь показывают `manual`.

## Risks / Trade-offs

- **Устаревший порядок после записи.** Порядок списка считает сервер, поэтому после записи список перечитывается, а не правится на месте. Между ответом записи и перечитыванием строка может на мгновение стоять по-старому; это приемлемо.
