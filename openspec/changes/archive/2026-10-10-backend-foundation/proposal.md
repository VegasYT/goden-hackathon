# Proposal

## Why

В `backend/` сейчас только каркас каталогов: нет Go-модуля, Event Store и согласованного списка доменных событий. Пока этого нет, разработчики A (запись) и B (чтение и интеграции) не могут работать параллельно: B нечем наполнять проекции, а A некуда писать события. Изменение закрывает часть разработчика A из этапа 0 в [backend/plan.md](../../../backend/plan.md): задачи 0.1, 0.2, 0.3 и черновик каталога событий 0.7.

## What Changes

- Инициализируется Go-модуль backend: `go.mod` с закреплённым toolchain, конфиг golangci-lint v2 с правилами `depguard` для границ модулей.
- Появляются платформенные пакеты: конфигурация из переменных окружения, `clock.Clock` с управляемой подделкой для тестов, JSON-логгер на `log/slog` с correlation ID, пул PostgreSQL и помощник транзакций.
- Появляется механизм миграций и первая миграция: таблица событий по ADR-002 с `position`, `txid`, уникальностью версии потока и запретом изменения и удаления строк на уровне базы.
- Появляется пакет `eventstore`: добавление событий в поток с проверкой ожидаемой версии, чтение потока, чтение всех событий в порядке `(txid, position)` ниже границы `pg_snapshot_xmin`.
- Появляется черновик каталога доменных событий: файлы `events.go` в модулях `catalog`, `inventory`, `orders` с 15 событиями из задачи 0.7, их потоками, полями и версиями схем. Черновик проходит согласование с разработчиком B через ревью.
- Появляется тестовая обвязка: PostgreSQL в testcontainers-go с изолированной базой на каждый тест и помощник, который добавляет готовые события в Event Store. Этим помощником B наполняет свои проекции, не дожидаясь команд A.
- Появляется `cmd/migrate`: применяет миграции к базе из окружения. Это единственная исполняемая точка в изменении, она же проверяет связку "конфигурация, логгер, база".
- Проверяется работа sqlc на Windows, результат фиксируется в `backend/AGENTS.md`.
- `backend/AGENTS.md` получает раздел с командами сборки, тестов, линтера и миграций.

Вне изменения остаются задачи разработчика B из этапа 0: `docker compose` (0.4), контракт `api/openapi.yaml` и проверка ogen (0.5), `cmd/api` и `cmd/worker` с health checks (0.6). Также вне изменения: advisory-блокировки по продуктам и идемпотентность команд (A1), таблица checkpoints и движок проекций (B1), любые команды, агрегаты и HTTP-эндпоинты.

## Capabilities

### New Capabilities

- `event-store`: хранение доменных событий в PostgreSQL - добавление в поток с проверкой версии, неизменяемость, чтение потока и чтение всех событий без пропусков при параллельной записи.
- `domain-events`: каталог доменных событий системы - типы, потоки, обязательные поля, версии схем и формат сериализации, общий контракт между записью и чтением.
- `backend-platform`: общая платформа backend-процессов - конфигурация из окружения, управляемые часы, структурированные логи, транзакции и миграции базы данных.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спецификации.

## Impact

- **Код:** новые файлы в `backend/`: `go.mod`, `.golangci.yml`, `cmd/migrate/`, `internal/platform/{config,clock,observability,postgres,eventstore}/`, `internal/{catalog,inventory,orders}/events.go`, `migrations/`. Файлы `.gitkeep` в заполненных каталогах удаляются.
- **Зависимости:** pgx v5, goose v3 (как библиотека), caarlos0/env v11, google/uuid, testify, testcontainers-go с модулем postgres.
- **Документы:** `backend/AGENTS.md` - команды и уточнение про goose. Архитектурные решения из `docs/ADR.md` не меняются: изменение реализует ADR-002 в части хранения и чтения событий.
- **Окружение разработчика:** для интеграционных тестов нужен запущенный Docker. Go 1.27 скачивается автоматически по директиве `toolchain`.
- **Разработчик B:** после слияния получает модуль, `eventstore`, каталог событий и тестовый помощник. Его задачи 0.4-0.6 с этим изменением по файлам не пересекаются, кроме `go.mod`.
- **Frontend и infra:** не затрагиваются.
