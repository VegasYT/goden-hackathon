# Spec Delta

## Purpose

Централизованные логи позволяют искать и сопоставлять вывод контейнеров системы в Grafana без доступа к Docker-хосту.

## ADDED Requirements

### Requirement: Сбор контейнерных логов
Promtail SHALL собирать stdout и stderr контейнеров текущего compose-проекта и доставлять записи в Loki. Каждая запись SHALL иметь стабильные labels окружения, compose-проекта, compose-сервиса и потока вывода; идентификаторы контейнеров и поля прикладного лога SHALL оставаться содержимым записи, а не labels.

#### Scenario: Лог backend-контейнера
- **WHEN** контейнер API записывает сообщение в stdout
- **THEN** сообщение появляется в Loki с labels окружения, проекта, сервиса `api` и потока `stdout`

#### Scenario: Контейнер пересоздан
- **WHEN** compose пересоздаёт контейнер сервиса под новым идентификатором
- **THEN** новые записи доступны по прежним labels проекта и сервиса без новой настройки

#### Scenario: Чужой compose-проект
- **WHEN** на том же Docker-хосте пишет лог контейнер, не относящийся к текущему compose-проекту
- **THEN** его запись не попадает в Loki этого проекта

### Requirement: Поиск логов в Grafana
Grafana SHALL иметь provisioned источник Loki и позволять без ручной настройки выбирать логи по окружению и compose-сервису. Отсутствие подходящих записей SHALL возвращать пустой результат, а не ошибку источника данных.

#### Scenario: Поиск по сервису
- **WHEN** оператор открывает Explore и выбирает сервис `worker`
- **THEN** Grafana показывает записи worker и не показывает записи других сервисов

#### Scenario: Логов нет
- **WHEN** запрос не находит записей за выбранный период
- **THEN** Grafana показывает пустой результат без ошибки подключения к Loki

### Requirement: Структурированные и текстовые записи
JSON-логи backend SHALL оставаться доступными для фильтрации по `level`, `msg` и `correlation_id` на этапе запроса. Поле `level` SHALL различать `DEBUG`, `INFO`, `WARN` и `ERROR`. Неструктурированный вывод инфраструктурных сервисов SHALL сохраняться и отображаться как исходный текст.

#### Scenario: Поиск по correlation ID
- **WHEN** API записал JSON-сообщения с заданным `correlation_id` и оператор фильтрует по нему в Grafana
- **THEN** результат содержит связанные записи с этим `correlation_id`

#### Scenario: Обычный текст
- **WHEN** сервис записывает строку, которая не является JSON
- **THEN** строка доступна в Grafana без потери исходного текста

#### Scenario: Фильтрация по уровню
- **WHEN** в Loki есть записи backend уровней `DEBUG`, `INFO`, `WARN` и `ERROR`, а оператор фильтрует поле `level` по одному из этих значений
- **THEN** Grafana показывает записи выбранного уровня и не показывает записи остальных уровней

### Requirement: Уровень не фильтруется при доставке
Promtail SHALL доставлять в Loki все записи, которые backend сформировал после применения своего минимального уровня, и SHALL NOT отбрасывать их по полю `level`.

#### Scenario: DEBUG сформирован приложением
- **WHEN** backend сформировал запись уровня `DEBUG`
- **THEN** Promtail доставляет её в Loki, и запись доступна запросу Grafana

#### Scenario: Одновременно записаны разные уровни
- **WHEN** backend сформировал записи уровней `INFO` и `ERROR`
- **THEN** обе записи доступны в Loki с исходными значениями поля `level`

### Requirement: Изоляция отказа хранилища логов
Недоступность Loki или Promtail SHALL NOT останавливать прикладные и инфраструктурные сервисы. После восстановления конвейера новые контейнерные записи SHALL снова становиться доступными в Grafana без перенастройки приложений.

#### Scenario: Loki временно недоступен
- **WHEN** Loki остановлен, а API продолжает обрабатывать запросы
- **THEN** API остаётся доступным, а после запуска Loki новые записи API появляются в Grafana

### Requirement: Хранение серверных логов
Серверное окружение SHALL сохранять данные Loki и позицию чтения Promtail между обычными пересозданиями контейнеров и SHALL автоматически удалять записи старше семи суток. Полный сброс томов SHALL удалять сохранённые логи и позиции.

#### Scenario: Повторная выкладка
- **WHEN** серверные контейнеры пересозданы без удаления томов
- **THEN** логи моложе семи суток остаются доступны, а Promtail продолжает чтение с сохранённой позиции

#### Scenario: Истёк срок хранения
- **WHEN** записи старше семи суток
- **THEN** Loki удаляет их из доступного для запросов набора

#### Scenario: Полный сброс
- **WHEN** серверный compose останавливают с удалением томов и запускают снова
- **THEN** прежние логи и позиции Promtail отсутствуют
