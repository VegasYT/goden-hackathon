Часть репо: `backend/`, команды из папки `backend/`.

## 1. Отключённые точка и компания

- [x] 1.1 Блюдо на точке меняется только на работающей точке, каталог - только в работающей компании. Проверка: интеграционный тест - каждая операция записи на отключённой точке и в отключённой компании отвечает 409 и не пишет событий.

## 2. Повтор заказа

- [x] 2.1 Чтение сохранённого результата команды; оформление заказа и его обработчик возвращают сохранённый заказ до проверок. Проверка: интеграционный тест - после выключения блюда и после отключения точки повтор с тем же ключом возвращает тот же заказ, новый ключ получает 422 и 409, остаток не меняется.

## 3. Генератор

- [x] 3.1 Наполнение каталога по состоянию каталога. Проверка: интеграционные тесты - незаконченный набор доводится до конца, каталог со своим блюдом не меняется, прежние тесты наполнения проходят.
- [x] 3.2 Генератор не заказывает блюда, выключенные на точке. Проверка: интеграционные тесты - заказы не содержат выключенных блюд, при всех выключенных заказов нет и ошибок нет; учётная запись генератора читает блюда только той точки, где он включён.

## 4. Журнал отказов

- [x] 4.1 Операция и автор в записи об отказе в доступе. Проверка: модульный тест читает запись журнала для отказа по праву и отказа правила об управляющих.

## 5. Документация и итог

- [x] 5.1 `backend/AGENTS.md`. Проверка: упомянутые имена есть в коде.
- [x] 5.2 Полная проверка: `go build ./...`, `go test -tags=integration ./...`, линтер. Проверка: все команды завершаются без ошибок.

## Что проверить вручную

Нужны окружение разработки и запущенные API, worker и генератор.

- MUST Остановить генератор посреди наполнения пустого каталога (сразу после включения на точке новой компании) и запустить снова: в каталоге 11 продуктов и 5 блюд с рецептурами, заказы создаются.
- MUST Выключить блюдо на точке с работающим генератором: в журнале генератора нет ошибок заказов, в истории заказов точки нет новых заказов с этим блюдом.
- SHOULD Запрос сотрудника к операции без права оставляет в журнале API запись "access denied" с полями `operation`, `actor_type`, `actor_id`.
- SHOULD На отключённой точке `PUT /points/{id}/dishes/{dishId}` отвечает 409.
