# Proposal

## Why

У системы нет стороны чтения: записать поставку и заказ можно, а получить список поставок, остатки по складу или стоп-лист нельзя. Все эти данные по ADR-002 - асинхронные проекции Event Store, и каждой нужен один и тот же механизм: читать события без пропусков, применять их ровно один раз, помнить, где остановился, и уметь собрать себя заново. Без общего движка каждая проекция решала бы это по-своему. Это задача B1 из [backend/plan.md](../../../backend/plan.md); разработчик B задерживается, задачу выполняет разработчик A.

## What Changes

- Появляется пакет `platform/projection` - движок асинхронных проекций. Проекция описывается именем, версией, функцией применения события и функцией очистки своих таблиц; всё остальное делает движок.
- Движок читает события порциями в общем порядке `(txid, position)` ниже границы `pg_snapshot_xmin` и применяет их в одной транзакции с обновлением checkpoint: событие применяется ровно один раз даже при сбое посреди порции.
- Checkpoint хранится в новой таблице `projection_checkpoints`. Блокировка его строки на время порции не даёт двум экземплярам процесса применить одно событие дважды.
- Перестроение с нуля: при изменении версии проекции движок очищает её таблицы, сбрасывает checkpoint и применяет все события заново. Отдельной команды администратора нет.
- Метрики: отставание проекции в событиях, число применённых событий, ошибки, время последней успешной порции.
- Синхронное "догнать до конца" для тестов и для будущих тестов эндпоинтов чтения.

Ни одной настоящей проекции в этом изменении нет: они появятся в B2 (склад), B3 (стоп-лист) и B4 (сроки годности). Подключение движка к `cmd/worker` тоже переносится в B2 - вместе с первой проекцией, которую он будет запускать.

Вне изменения: мгновенное пробуждение проектора по уведомлению базы (сейчас - опрос с коротким периодом); ожидание проекции в запросах чтения ("прочитать свою запись"); publisher в Kafka (B6) - у него свой checkpoint и своя семантика подтверждения.

## Capabilities

### New Capabilities

- `projections`: движок асинхронных проекций - чтение без пропусков, применение ровно один раз, checkpoint, перестроение, отставание.

### Modified Capabilities

Нет.

## Impact

- **Код:** новый пакет `backend/internal/platform/projection/`; миграция таблицы checkpoint.
- **Документы:** `backend/AGENTS.md` (как написать проекцию, правила), `backend/plan.md` (статус B1, исполнитель).
- **Следующие задачи:** B2, B3, B4, B5, B8 пишут только функцию применения события и свои таблицы.
- **Поведение системы:** не меняется, пока нет проекций.
