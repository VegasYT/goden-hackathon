## Context

- Сейчас `startSession` собирает `Session` с правами из `resource_access` токена, `main.tsx` создаёт роутер с этой сессией, роуты разделов лежат в корне (`/stock`, `/deliveries`…), а `RootLayout` оборачивает в `AppShell` все роуты, включая `/dev/ui` и «не найдено».
- Профиль `GET /me` отдаёт компании пользователя и точки с `owner`, `role`, `permissions`, `active`. Первый запрос `/me` регистрирует пользователя на бэкенде: до него сотрудника нельзя назначить по почте.
- Слоёв `entities`, `features`, `widgets` во фронте ещё нет. Скилл FSD и алиасы `@entities/*` уже настроены.
- Макеты: холст «Goden — макеты интерфейса», страница «Точки и вход».

## Goals / Non-Goals

**Goals:** фронт работает с новым контрактом, права и роль берутся с выбранной точки, есть первый вход без ручной подготовки.

**Non-Goals:** управление компанией и точками, SSE по точке, экраны разделов (см. proposal).

## Decisions

### Сессия и профиль разделены

`shared/auth` отвечает только за личность и токены: `Session` теперь `{ userId, name }` (`sub` и `name`/`preferred_username` из токена). Статус `no-access` у `startSession` удаляется. Профиль — отдельный слайс `entities/profile`:
- `meQueryOptions` (ключ `['me']`) — запрос `/me` через `apiClient`;
- функции над профилем: найти точку по id, права и подпись роли на точке, отключена ли точка, список точек по компаниям;
- последняя выбранная точка в `localStorage` под ключом с `userId`, через `shared/lib/storage`.

Альтернатива — класть права в `Session` при запуске — отвергнута: права меняются во время работы (смена роли, снятие с точки), а Query уже умеет перечитывать при фокусе вкладки.

### Запуск

`main.tsx`: Keycloak (как сейчас) → `queryClient.fetchQuery(meQueryOptions)` → роутер. Ошибка `/me` показывает экран `pages/profile-unavailable` с «Повторить» (заново запрашивает профиль, Keycloak не трогает) и «Выйти». Профиль кладётся в тот же `QueryClient`, что получает роутер, поэтому `beforeLoad` берёт его из кэша без запроса. `staleTime` у профиля остаётся нулевым: при возврате на вкладку Query перечитает `/me`, а компоненты подписаны на `useQuery`.

### Дерево роутов

```
__root            Outlet + devtools, без оболочки
/                 beforeLoad: redirect на последнюю/первую точку или /welcome
/welcome          первый вход; есть точки -> redirect на /
/points/$pointId  layout: AppShell; beforeLoad ищет точку в профиле
  index           Сводка
  stock, deliveries, orders, kitchen, stop-list, analytics
/dev/ui           без оболочки
404               без оболочки
```

`AppShell` переезжает из `RootLayout` в layout точки: вне точки разделам некуда вести. `/dev/ui` и «не найдено» становятся экранами без оболочки (это витрина и ошибка, навигация им не нужна; решение выведено из структуры, не задано пользователем).

`beforeLoad` у `/points/$pointId` при отсутствии точки в профиле бросает `PointUnavailableError`; `errorComponent` этого роута показывает `pages/point-unavailable` в оболочке без пунктов разделов. Если точка пропала из профиля после перечитывания, layout показывает ту же страницу. При успешной загрузке layout запоминает точку как последнюю.

`requireSection(context, pointId, section)` проверяет право по профилю из кэша. Пункты навигации получают адреса вида `/points/$pointId/stock` с параметром выбранной точки.

### Переключатель

Компонент оболочки `app/layouts/app-shell/point-switcher.tsx` (виджет пока единственный потребитель, отдельный слой `widgets` не заводим). Смена точки: если у текущего раздела есть право на новой точке — тот же раздел, иначе «Сводка» и сообщение в `Snackbar` оболочки. Текущий раздел определяется по совпавшему роуту, а не разбором строки адреса. Одна точка в профиле — статичное название без меню. В узкой панели кнопка с инициалами точки открывает тот же список.

### Первый вход

`pages/welcome` с двумя шагами. Шаг выбирается по профилю: нет компаний → компания; есть своя работающая компания без точек → точка в ней. После `POST /companies` профиль перечитывается, и экран сам переходит ко второму шагу. После `POST /companies/{companyId}/points` профиль перечитывается и открывается «Сводка» новой точки.

Ключ идемпотентности (`Idempotency-Key`, `crypto.randomUUID()`) создаётся на одну попытку отправки и сохраняется до успеха или смены названия: повтор после обрыва связи не создаёт вторую компанию или точку. «Проверить снова» — `refetch` профиля; появилась точка → редирект на `/`.

### Подписи ролей

Словарь `Role -> подпись` в `entities/profile`: `manager` — «Управляющий», `approver` — «Приёмщик», `cook` — «Повар», `waiter` — «Официант»; владелец — «Владелец». Подпись в профиле оболочки берётся для выбранной точки.

### Тесты

`renderApp(path, { profile, tree })` кладёт профиль в `QueryClient` через `setQueryData`; по умолчанию профиль владельца с одной точкой и всеми правами. Запросы создания на первом входе мокаются на `apiClient`.

## Risks / Trade-offs

- **Перечитанный профиль убрал точку посреди работы.** Открытая страница не исчезнет сама до перехода или фокуса вкладки; бэкенд при этом отвечает 403/404 на запросы. Этого достаточно: права проверяет сервер.
- **Адреса меняются целиком.** Старые ссылки вида `/stock` ведут на «не найдено». Пользователей со старыми закладками нет, переадресацию не делаем.
- **Последняя точка хранится в браузере**, на другом устройстве откроется первая точка профиля. Это удобство, не состояние.
