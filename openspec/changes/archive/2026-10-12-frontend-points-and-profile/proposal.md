## Why

Бэкенд перешёл на компании и точки (ADR-013): прав в токене больше нет, а почти все операции API живут под `/points/{pointId}`. Фронт берёт права из ролей токена, поэтому сейчас любой вошедший видит «Нет доступа к приложению», а типы API описывают старые пути. Перед экранами фич фронт должен работать в новой модели.

## What Changes

- Права и роль на точке берутся из профиля `GET /api/v1/me`. Из токена остаются только имя и логин. Профиль загружается после входа, до показа приложения; если загрузить его нельзя, показывается экран с «Повторить» и «Выйти».
- **BREAKING:** все разделы переезжают под адрес точки: `/points/<точка>`, `/points/<точка>/stock` и т. д. Адрес `/` открывает последнюю выбранную точку пользователя, а если её нет — первую из профиля.
- Переключатель точки в боковой и узкой панели: точки сгруппированы по компаниям, у каждой роль; отключённые точки владельца помечены. При смене точки открывается тот же раздел, если на новой точке на него есть право, иначе «Сводка» с сообщением. У сотрудника одной точки вместо переключателя только её название.
- Точка из адреса, которой нет в профиле, открывает страницу «Точка недоступна».
- На отключённой точке владельца показывается плашка: данные только для чтения.
- Первый вход: пользователь без точек создаёт компанию, затем первую точку (если компания уже есть — только точку). Экран объясняет сотруднику, что его нужно добавить на точку, и даёт «Проверить снова».
- Подпись роли по-русски: Управляющий, Приёмщик, Повар, Официант; владельцу — «Владелец».
- Страница «Нет доступа к приложению» удаляется: её место занимает первый вход.
- Типы API перегенерируются по текущему `backend/api/openapi.yaml`.

Вне изменения:

- управление компанией и точками: переименование, отключение, сотрудники, чат Telegram, генератор, блюда на точке, передача компании (отдельная фича);
- поток обновлений SSE по точке и индикатор связи от реального источника (отдельное изменение realtime);
- экраны разделов: они остаются заглушками;
- создание второй компании пользователем, у которого уже есть точки.

## Capabilities

### New Capabilities

- `frontend-points`: выбор точки — точка в адресе, переключатель, последняя точка, недоступная и отключённая точка, первый вход с созданием компании и точки.

### Modified Capabilities

- `frontend-auth`: профиль из `/me` до показа приложения и его ошибка, подписи ролей и владельца; требование о пользователе без компаний и точек переходит в первый вход `frontend-points`.
- `frontend-shell`: навигация ведёт на разделы выбранной точки.

## Impact

- `frontend/`: `src/shared/auth` (сессия без прав из токена), новый слой профиля и точки, `src/app` (запуск, роуты под `/points/$pointId`, проверка раздела, оболочка, переключатель), `src/pages` (первый вход, «Точка недоступна», ошибка профиля; удаление `no-access`), `src/shared/api/schema.gen.ts`, тестовые хелперы, `AGENTS.md` и скилл `frontend-testing`.
- Контракт `backend/api/openapi.yaml` не меняется: фронт догоняет уже изменённый контракт, используются `/me`, `POST /companies`, `POST /companies/{companyId}/points`.
- Решение следует ADR-013, не меняет его.
