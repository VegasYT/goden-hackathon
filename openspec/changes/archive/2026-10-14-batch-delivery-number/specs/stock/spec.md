## MODIFIED Requirements

### Requirement: Чтение партий продукта
Система SHALL возвращать партии продукта с идентификатором, остатком, исходным количеством, датой окончания срока годности, временем поступления, ссылкой на поставку и номером этой поставки. Партии SHALL быть упорядочены по дате окончания срока годности от ближайшей к дальней, а при равных датах по времени поступления. Данные SHALL отражать все завершённые команды склада без задержки.

Номер поставки SHALL быть в каждом ответе с партией: список партий продукта, партия по идентификатору, список истекающих партий, ответы списания и корректировки.

#### Scenario: Порядок FEFO
- **WHEN** у продукта есть партии со сроками 20, 12 и 15 октября
- **THEN** партии возвращаются в порядке 12, 15, 20 октября

#### Scenario: Продукт без партий
- **WHEN** запрашивают партии продукта, по которому не было принятых поставок
- **THEN** возвращается пустой список

#### Scenario: Чтение сразу после приёмки
- **WHEN** приёмка завершена и сразу после этого запрашивают партии продукта
- **THEN** новые партии возвращаются с номером принятой поставки

#### Scenario: Партии из двух поставок
- **WHEN** у продукта есть партии из поставок с номерами "Н-1" и "Н-2"
- **THEN** у каждой партии указан номер своей поставки

### Requirement: Склад в HTTP API
Система SHALL предоставлять через HTTP API чтение партий продукта в порядке FEFO, чтение партии по идентификатору, ручное списание из партии и корректировку остатка партии по правилам возможности `http-api`. Списание и корректировка SHALL возвращать статус 200 и партию с новым остатком.

Причина списания SHALL принимать только значения из набора `expired`, `transport_damage`, `storage_violation`, `physical_damage`, `quality_issue`, `other`; другое значение отклоняется контрактом со статусом 400, как и неположительное количество списания и запрос списания без поля комментария. Нарушения правил предметной области (списание больше остатка, пустой комментарий, причина `expired` для годной партии, нулевая корректировка, уменьшение больше остатка) дают статус 422 с указанием поля; несуществующая партия - статус 404.

Операции, предназначенные для автоматического вызова - списание просроченной партии и предупреждение о сроке годности, - SHALL NOT быть доступны через HTTP API.

#### Scenario: Партии продукта
- **WHEN** отправляют `GET /api/v1/products/{id}/batches` для продукта с тремя партиями
- **THEN** возвращается статус 200 и партии в порядке возрастания даты окончания срока годности с остатком и исходным количеством

#### Scenario: Ручное списание
- **WHEN** отправляют `POST /api/v1/batches/{id}/write-offs` с количеством 300, причиной `storage_violation` и комментарием
- **THEN** возвращается статус 200 и партия с остатком, уменьшенным на 300

#### Scenario: Списание больше остатка
- **WHEN** списание отправляют с количеством больше остатка партии
- **THEN** возвращается статус 422 с указанием поля `quantity`

#### Scenario: Неизвестная причина списания
- **WHEN** списание отправляют с причиной, не входящей в набор
- **THEN** возвращается статус 400

#### Scenario: Списание без поля комментария
- **WHEN** списание отправляют без поля `comment`
- **THEN** возвращается статус 400

#### Scenario: Списание с пустым комментарием
- **WHEN** списание отправляют с комментарием из одних пробелов
- **THEN** возвращается статус 422 с указанием поля `comment`

#### Scenario: Корректировка остатка
- **WHEN** отправляют `POST /api/v1/batches/{id}/adjustments` с изменением -50 и причиной
- **THEN** возвращается статус 200 и партия с остатком, уменьшенным на 50

#### Scenario: Несуществующая партия
- **WHEN** отправляют чтение, списание или корректировку для партии, которой нет
- **THEN** возвращается статус 404

### Requirement: Движения по продукту
Система SHALL отдавать движения по продукту через `GET /api/v1/products/{productId}/movements`: записи о получении партий, расходе по заказам, списаниях, корректировках остатка и предупреждениях о сроке, от последних к ранним, постранично, с общим числом. Запись SHALL содержать вид движения, время, автора и изменения остатка по партиям со знаком; для расхода - заказ, для получения - поставку, для списания и корректировки - причину и комментарий. Каждое изменение SHALL содержать номер поставки своей партии, в том числе для партии с нулевым остатком. Сумма изменений по партии во всех движениях SHALL равняться её текущему остатку. Для продукта, которого нет в каталоге, SHALL возвращаться статус 404. Операция SHALL требовать право `inventory.view`.

#### Scenario: Полный путь партии
- **WHEN** партия получена на 100, заказ израсходовал 30, списано 20, корректировка добавила 5
- **THEN** движения продукта, от последнего к первому: корректировка +5, списание -20 с причиной, расход -30 с заказом, получение +100 с поставкой; сумма изменений равна остатку 55

#### Scenario: Расход из двух партий
- **WHEN** заказ израсходовал продукт из двух партий разных поставок
- **THEN** это одно движение с двумя изменениями по партиям, у каждого изменения номер своей поставки

#### Scenario: Движение по пустой партии
- **WHEN** партия списана целиком и запрашивают движения продукта
- **THEN** изменения по этой партии содержат номер её поставки

#### Scenario: Автор движения
- **WHEN** списание выполнил пользователь, а расход - заказ, оформленный другим пользователем
- **THEN** у каждого движения указан свой автор

#### Scenario: Пагинация
- **WHEN** у продукта пять движений и запрашивают страницу размером два со смещением два
- **THEN** возвращаются третье и четвёртое с конца, общее число равно пяти

#### Scenario: Продукт без движений
- **WHEN** продукт есть в каталоге, поставок не было
- **THEN** возвращается пустой список и общее число ноль

#### Scenario: Неизвестный продукт
- **WHEN** запрашивают движения продукта, которого нет в каталоге
- **THEN** возвращается статус 404
