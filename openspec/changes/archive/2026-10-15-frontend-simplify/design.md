## Context

Мотивация — в proposal.md. Список правок собран девятью ревью по всему `frontend/src`: семь по частям кода и два по находкам, отложенным прошлыми `/simplify`. Видимые правки согласованы на странице холста «Simplify: видимые правки». Слои FSD проверяет steiger: страница не импортирует другую страницу, нижний слой не импортирует верхний. Поэтому общее между страницами уходит в `entities` (предметное) или `shared` (без предметной области). Проверено в коде:
- `PointLayout` рисует дочерние роуты только при найденной точке;
- MUI `Dialog` сам связывает заголовок через контекст;
- `ApiError.status` есть у ответов сервера и пуст при обрыве связи;
- steiger пропускает `entities/<слайс>/index.testing.ts` как публичный API слайса.

## Goals / Non-Goals

**Goals:**
- Одно место для каждого повторяющегося куска; страницы только собирают его под свой текст.
- Правки идут пачками, после каждой зелёный `pnpm check`, чтобы ошибку было видно сразу.

**Non-Goals:**
- Новые функции, правки контракта и бэкенда.
- Перенос записей из `entities` в страницы: это противоречит раскладке, описанной в `frontend/AGENTS.md`.

## Decisions

**Один `QueryClient` для приложения и тестов.**
- Где: `app/query-client.ts` — `createQueryClient({ test })`.
- По умолчанию `staleTime: pointDataFreshMs` и повтор только при `status` пустом или ≥ 500.
- Явные исключения остаются у своих запросов: профиль `/me` (`staleTime: 0`, его перечитывает возврат на вкладку), каталог компании (`catalogFreshMs` = 5 мин), карточка карантина перед решением (`staleTime: 0`).
- Тесты получают тот же клиент с `retry: false` вместо `staleTime: Infinity`, чтобы разрыв свежести был виден и в тестах.
- Альтернатива — дописать `staleTime` в пять забытых запросов. Отклонена: забытый шестой снова пройдёт молча.

**Ключи и чтение данных.**
- `pointKey(pointId)` в `shared/lib/query`. От него строятся фабрики ключей точки, как каталог от `catalogKey`.
- `getData(url, params)` в `shared/api` — `queryFn` вместо 28 одинаковых `(await apiClient.get(...)).data`.
- Запись получает заголовок только через `idempotencyHeader`, ключ формы — только через `useIdempotencyKey`. Генератор тоже: новое нажатие несёт новое `delivered_at`, значит и новый ключ, как требует спека генератора.

**Помеченное устаревшим не обрывает начатый запрос.**
- Своя запись, сигнал потока и `invalidateLater` помечают данные через один помощник `invalidateKeys` с `cancelRefetch: false`.
- У `invalidateLater` предел ожидания 3000 мс: первый отложенный вызов по ключу запоминает время. Если с него прошло больше предела, срок не переносится. После срабатывания запись удаляется, поэтому вызов после серии даёт ещё одно перечитывание.

**Точка из адреса — в контексте роута.**
- `beforeLoad` у `/points/$pointId` возвращает `{ point }`.
- `requireSection(point, section)` и новый `requirePermission(point, permission, section)` синхронные.
- Страницы берут точку через `usePoint(pointId)` из `entities/profile`. Он читает профиль из кэша и возвращает найденную точку: без неё `PointLayout` до страницы не доходит.
- Layout'ы разделов тоже берут точку через `usePoint`, а не из контекста роута. Контекст — снимок на момент перехода, а профиль перечитывается.
- Тест-роутер собирается теми же `appRouterOptions`, что приложение.

**Подпись автора — слайс `entities/actor`.**
- Состав: `Actor`, `actorName`, `isMigom`. Сейчас это знание лежит в `shared` и частично повторено в `entities/delivery`.
- `actorLabel` поставок удаляется; поставки, горячие предложения и склад зовут `actorName`.
- Фразы с глаголом строятся как «<что> уже <принята/решён>: <автор>, <время>», чтобы род глагола не зависел от автора («Система», «Генератор»).

**Общие компоненты в `shared/ui`.**
- `QueryState`: заготовка, ошибка с «Повторить», данные. Принимает объект запроса (`isPending`, `error`, `isFetching`, `refetch`). `LoadErrorState` тоже принимает `query`.
- `CardList` и `CardListItem` на `Card` темы: радиус `lg`, кольцо `divider`.
- `NoResultsState`, `RetryAlert`, `useLeaveConfirm` (хук, а не компонент: условие читает ref, и React Compiler пропускает это только в аргументе хука).
- `Breadcrumbs`, `SectionTabs`, `TimelineItem`, `SortableHeaderCell`, `useNotice`, `DisclosureIcon`, `EmptyValue`.
- `usePagedSearch`: последняя страница и сброс на первую при смене фильтра. У `ListPagination` линия сверху по умолчанию только в карточном виде.
- Пояснение «только чтение» по `WriteAccess` — `AccessNote` в `entities/profile`: он знает тип доступа.

**Тема.**
- У `MuiAlert` появляется нейтральный вариант `info` с фоном поля, кольцом и серым значком (как `KcAlert`), значки всех плашек задаёт `defaultProps.iconMapping` из нашего набора.
- `MuiDialogTitle` по умолчанию `variant='h2'`, у `MuiDialogActions` отступы `8px 24px 24px` и `gap`. Связка `useId` в диалогах удаляется.
- `FormDialog` получает `maxWidth` и необязательный `pending`. На нём собираются диалоги списания, исправления остатка и «Свой период».
- Цвет заголовков h1–h3 — через `themeVars` в `MuiTypography`. Радиус в `sx` — помощник `radius(theme, size)`.
- Скрипт ранней установки темы собирается плагином Vite из того же ключа, что `colorModeStorageKey`.

**Формы.**
- Диалоги склада переходят на TanStack Form, как требует `frontend/AGENTS.md`. Ошибки по-прежнему считаются в рендере по живому остатку партии.
- Обязательные поля приёмки и карантина краснеют по `isBlurred` поля или после попытки подтвердить; текст «обязателен» виден сразу серым.
- Селекторы стора формы сравниваются одним `shallowEqual` из `shared/lib`, без самодельных кодировок.

**Тесты.**
- Фикстуры сущностей — `entities/<слайс>/index.testing.ts` (продукт, поставка, позиция); `app/test-*.ts` их реэкспортируют.
- Профили ролей — одна карта прав ролей и `testStaffPoint(role)` в `app/test-router.tsx`.
- `mockReset: true` и `vi.useRealTimers()` — в общей настройке Vitest. `renderApp` по умолчанию включает широкий экран, планшетные тесты передают `wide: false`.

## Risks / Trade-offs

- [Тесты считали запросы под `staleTime: Infinity`] → после общего клиента часть ожиданий числа запросов поменяется. Правим ожидания, только если новое число соответствует спеке, а не подгоняем.
- [`mockReset: true` сбросит моки, на которые неявно опирались соседние тесты] → такие тесты задают свои моки явно в `beforeEach`.
- [Пачка задевает много файлов] → после каждой пачки `pnpm check`, чтобы поломка не уехала в следующую.
- [Предел ожидания чаще перечитывает тяжёлые списки при работающем генераторе] → не чаще раза в 3 с на ключ, это дешевле, чем «замершая» история.
