# Proposal

## Why

Каталог (раздел 10 чек-листа) владелец пока заполняет только генератором. API для поиска, изменения и архива продуктов и блюд уже в `develop` (изменение `catalog-management`). Макеты лежат на странице холста «Каталог». Это последний раздел интерфейса без экрана.

## What Changes

- Раздел «Каталог» по адресу `/points/<точка>/catalog` только для владельца. Он показывает каталог компании выбранной точки, а в меню встаёт первым пунктом группы «Компания «<название>»».
- **Вкладка «Продукты».**
  - Поиск по части названия, фильтр по категории, переключатель «Действующие / Архив», сортировка по названию или категории. Состояние списка хранится в адресе, фильтры, сортировку и страницы считает сервер.
  - Столбцы: категория, единица, срок хранения, в скольких блюдах продукт.
  - Новый продукт и изменение продукта: название, единица, категория из списка категорий или новая, срок хранения или «без срока». Единица заблокирована, если продукт уже использовался.
  - Архив с отказом, если продукт есть в рецептурах. Восстановление из архива.
- **Вкладка «Блюда».**
  - Поиск, переключатель «Действующие / Без рецептуры / Архив».
  - Рецептура на порцию одной строкой. Блюдо без рецептуры подсвечено: оно в стоп-листе.
  - Новое блюдо сразу с рецептурой.
  - Панель блюда: переименование и редактор рецептуры. Продукт ищется на сервере, количества в граммах, миллилитрах и штуках. Если продукта нет, его можно создать прямо из поиска, и он сразу попадёт в рецептуру.
  - Архив блюда, восстановление с отказом, если в рецептуре есть архивный продукт.
- **Ошибки у поля.** «Название занято», в том числе продуктом или блюдом в архиве, показывается у поля названия.
- **Обновление в реальном времени.** Сигнал `catalog` перечитывает данные каталога.
- **Новая поставка.** Продукт в позиции ищется на сервере по всему каталогу, а не среди первых 200. Поле выбора продукта общее с редактором рецептуры.
- **Подготовка.** Пересоздание типов API (`pnpm api:types`), новое обязательное поле `archived` в тестовых данных, строка `catalog` в таблице сигналов. Фильтр категорий на складе берёт список категорий с сервера, а не из первых 200 продуктов.
- Вне изменения:
  - удаление продуктов и блюд (в API его нет);
  - цены и себестоимость;
  - отдельные рецептуры для точек;
  - каталог для сотрудников: им рецептуры видны на «Кухне».

## Capabilities

### New Capabilities
- `frontend-catalog`: раздел «Каталог» — продукты, блюда, рецептуры, архив.

### Modified Capabilities
- `frontend-shell`: «Навигация по разделам» — в группе компании появляется «Каталог».
- `frontend-realtime`: «Перечитывание по категориям сигнала» — категория `catalog`.
- `frontend-deliveries`: «Форма новой поставки» — продукт ищется на сервере по всему каталогу, архивные не предлагаются.

## Impact

- frontend:
  - пересозданный `src/shared/api/schema.gen.ts`;
  - тестовые данные с продуктами;
  - `src/app/realtime/point-signals.ts`;
  - `nav-items.ts`;
  - новый роут `points.$pointId.catalog.tsx` и страница `src/pages/catalog`;
  - запросы и записи каталога в `src/entities/product` и `src/entities/dish`;
  - категории склада в `src/pages/stock`;
  - поле продукта в `src/pages/delivery-new`.
- backend и контракт не меняются.
