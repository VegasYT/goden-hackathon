# Design

## Context

Мотивация описана в `proposal.md`, требования — в `specs/frontend-design-system` и `specs/frontend-shell`.

**Что уже есть в `frontend/`:**
- Vite 8, React 19 с React Compiler, MUI 9.5, TanStack Router (файловые роуты в `src/app/routes`, дерево роутов коммитится), Vitest, линтеры (ESLint, Stylelint, Steiger), Prettier;
- алиасы по слоям FSD: `@app/*`, `@pages/*`, `@shared/*` и т.д.;
- тема в `src/shared/ui/theme/theme.ts`: `createTheme` с `cssVariables: { colorSchemeSelector: 'class' }` и стартовой палитрой прошлого проекта;
- `main.tsx` оборачивает `RouterProvider` в `ThemeProvider` и `CssBaseline`;
- корневой layout `src/app/layouts/root-layout.tsx` содержит только `Outlet` и devtools;
- одна страница `pages/dashboard`;
- `@mui/icons-material` установлен, но не используется.

**Визуальное направление согласовано** на макетах «Goden — макеты интерфейса» (артефакт https://claude.ai/artifact/Dv7qjRJM1w5ybMVUd2aUWR, приватный: владелец открывает доступ команде). Там:
- экран приёмки поставки на ноутбуке 1440×900 и планшете 820×1180 в обеих темах;
- drawer открытого карантина;
- диалог подтверждения;
- состояние «нет связи».

Значения токенов ниже взяты из этих макетов и проверены на контраст.

**Ограничения:**
- в UI нет моноширинного шрифта;
- шрифт и иконки не грузятся с внешних CDN;
- `shared` не содержит бизнес-логики (правило FSD);
- `pnpm check` должен проходить.

## Goals / Non-Goals

**Goals:**
- Один источник значений: TS-объект токенов. Из него строится тема MUI, его же читают тест контраста и витрина.
- Новый экран собирается из темы и компонентов `shared/ui` без единого hex-кода и без локальных переопределений MUI.
- Решения записаны в скилле `frontend-design-system`. По нему агент и человек делают новый экран в той же системе.

**Non-Goals:**
- Свой UI-кит поверх MUI. Используем компоненты MUI и настраиваем их через тему. Своё пишем только там, где у MUI нет нужного: поле количества, панель действий, индикатор связи.
- Storybook. Его заменяет витрина `/dev/ui`.
- Анимации иконок. Решено, что от них, скорее всего, откажемся.
- Переключение плотности вручную. Плотность определяется способом ввода.

## Decisions

### 1. Где лежит дизайн-система (FSD)

```
src/shared/ui/theme/        tokens.ts (значения обеих тем), theme.ts (createTheme),
                            components.ts (переопределения), typography.ts,
                            contrast.ts + contrast.test.ts, mode-toggle.tsx,
                            augment.d.ts (типы MUI), index.ts
src/shared/ui/icon/         icons.ts (реестр используемых иконок), icon.tsx, index.ts
src/shared/ui/<component>/  page-header, quantity-field, segmented-control,
                            action-bar, confirm-dialog, empty-state,
                            connection-status, logo — у каждого index.ts
src/shared/lib/storage/     безопасная обёртка над localStorage (try/catch)
src/shared/lib/test-utils/  renderWithTheme для тестов компонентов
src/app/layouts/app-shell/  оболочка: сайдбар, рельс, конфигурация навигации
src/pages/section-stub/     страница «раздел в разработке»
src/pages/dev-ui/           витрина
```

Тема и базовые компоненты лежат в `shared/ui`, потому что не знают о предметной области.

Оболочка лежит в `app/layouts`: она общая для всего приложения и собирает навигацию из конфигурации. Слой `widgets` не вводим, FSD 2.1 не советует его без необходимости.

Переключатель темы — это обёртка над хуком MUI без бизнес-логики, поэтому он в `shared/ui/theme`, а не в `features`.

Отвергнуто:
- **токены в JSON или только CSS-переменными.** Тесту контраста и витрине нужны значения в JS, а TS-объект даёт типы.

Как токены ложатся на палитру MUI:
- `background.default = canvas`, `background.paper = paper`, `divider = line`;
- `primary`: `main = brand`, `contrastText = onBrand`, плюс дополнительные поля `ink`, `tint` и `onTint`;
- `warning` и `error` устроены так же: `main = Fill`, плюс поля `ink`, `tint` и `onTint`;
- `success` совпадает с `primary`;
- `text.primary = ink2`, `text.secondary = ink3`, плюс дополнительные `text.strong = ink1` и `text.tertiary = ink4`;
- новые ключи палитры: `field`, `track`, `lineStrong`, `lineInput`, `neutralFill`, `overlay`.

Типы расширяются в `augment.d.ts`.

**Отличие от макетов.** Граница полей ввода (`lineInput`) темнее, чем на макетах. Спека требует 3:1 для границ полей, а полупрозрачная линия макета даёт около 1.4:1. Выбрано самое светлое значение, которое проходит порог: 3.35:1 на `paper` в светлой теме и 3.49:1 в тёмной. Разделители и рамки карточек остаются полупрозрачными: они декоративные и под требование не попадают.

Отвергнуто:
- **зелёный бренд для статуса «свежий».** Зелёный тогда означал бы и действие, и статус.
- **плотность и цвета, заданные отдельными темами для планшета.** Удвоило бы число тем без пользы.

### 3. Тест контраста

`contrast.ts` содержит:
- функцию относительной яркости и контраста по WCAG 2.x;
- смешивание полупрозрачного цвета с фоном;
- список проверяемых пар с порогами.

`contrast.test.ts` проверяет пары для обеих тем. При ошибке он выводит имя пары и фактический контраст.

| Порог | Пары |
|---|---|
| 4.5:1 | `ink1`–`ink4` на `paper` и `canvas`; `ink1`–`ink3` на `track`; `brandInk`, `warnInk`, `dangerInk` на `paper`; `onBrand` на `brand`; `*OnTint` на соответствующем `*Tint` (полупрозрачный смешивается с `paper`) |
| 3:1 | `lineInput` на `paper`, `field` и `canvas`; `warnFill`, `dangerFill`, `neutralFill` на `paper`; `brandInk` (кольцо фокуса) на `paper` и `canvas` |

Сознательно не проверяем:
- **`ink4` на `track`** (4.18:1). Правило: на `track` третичный текст не используется, неактивные варианты переключателя берут `ink3`.
- **заливку `brand` против белого фона** (2.3:1). Кнопку определяет подпись с контрастом 6.5:1, и WCAG 1.4.11 этого не требует.
- **полоску прогресса.** Она дублирует текст «7 из 8 решено».

### 4. Типографика

- **Шрифт.** Golos Text Variable из пакета `@fontsource-variable/golos-text`, импортируется в `main.tsx`. Используем насыщенности 400, 500 и 600.
- **Табличные цифры** включены глобально (`font-variant-numeric: tabular-nums` на `body` через `CssBaseline`). Фича `tnum` есть в шрифте и затрагивает только цифры.
- **Шкала** с шагом около 1.25 от базы 14px:

| Вариант | Назначение | Размер / насыщенность | На планшете |
|---|---|---|---|
| `h1` | заголовок страницы | 26 / 600, трекинг −0.02em | 26 |
| `h2` | заголовок диалога, drawer | 20 / 600, −0.01em | 20 |
| `h3` | заголовок секции | 15 / 600 | 17 |
| `body1` | основной текст | 14 / 400, высота строки 1.45 | 15 |
| `body2` | вторичный текст | 13 / 400 | 14 |
| `caption` | метаданные | 12 / 400 | 13 |
| `button` | кнопки | 14 / 600, без капса | 16 |

Заголовки получают `text.strong`. Варианты `h4`–`h6`, `subtitle*` и `overline` не используются и в скилле помечены как запрещённые.

### 5. Отступы, радиусы, глубина

- **Отступы.** `theme.spacing` остаётся 8px (на нём основаны внутренние отступы MUI), шаг 4px — это `0.5`. Используемые значения: 4, 8, 12, 16, 20, 24, 32.
- **Радиусы.** Шкала в `theme.shape` (расширение типа): `xs 4` (чипы), `sm 6` (кнопки и поля на ноутбуке), `md 8` (поля на планшете, пункты навигации), `lg 12` (карточки), `xl 14` (диалоги). `borderRadius` по умолчанию равен 6.
- **Глубина** передаётся одним способом.
  - Элементы в потоке страницы: тонкая рамка `box-shadow: 0 0 0 1px line`, у `Paper` `elevation: 0`.
  - Тени только у всплывающих слоёв (меню, popover, диалог, drawer): мягкая тень и рамка `line`.

### 6. Плотность по способу ввода

**Размеры элементов** задаются по медиазапросу `(pointer: coarse)` внутри `styleOverrides` и типографики:
- **ноутбук:** поля и кнопки 32–40px;
- **планшет:** не меньше 44px, кнопки −/+ 44×44, основная кнопка 48px.

**Раскладка оболочки** переключается по ширине: 1200px, брейкпоинт `lg` подстраивается под это значение.

Это два независимых признака. Ноутбук с узким окном получает рельс, но компактные элементы. Планшет в альбомной ориентации получает рельс и крупные элементы.

Отвергнуто:
- **плотность по ширине окна.** Узкое окно на ноутбуке получило бы крупные элементы без причины, а планшет в альбомной ориентации (1180px) — мелкие.

### 7. Переопределения MUI

Все переопределения живут в `components.ts`:
- **`MuiButtonBase`:** `disableRipple`.
- **`MuiButton`:**
  - `disableElevation`, без капса;
  - вариант `contained` используется только с цветом `primary`;
  - `outlined` — вторичная кнопка: фон `paper`, рамка `lineStrong`;
  - `text` — тихая кнопка;
  - размеры по разделу 6, `white-space: nowrap`.
- **`MuiIconButton`:** размеры по разделу 6.
- **Поля ввода:**
  - `MuiTextField` по умолчанию с постоянно сжатой подписью;
  - подпись стоит над полем, вырез рамки отключён;
  - `MuiOutlinedInput`: фон `field`, граница `lineInput`, фокус — кольцо 3px из `brand` с прозрачностью и граница `brandInk`.
- **`MuiChip`:**
  - радиус `xs`, малый размер;
  - цвета `warning` и `error` дают `tint`/`onTint`, `default` — контур `lineStrong`.
- **`MuiPaper`, `MuiCard`:** без теней, с рамкой `line`, радиус `lg`.
- **`MuiTableCell`:**
  - отступы 10/12 на ноутбуке и 14/16 на планшете;
  - заголовок 12/500 цветом `ink4` без капса;
  - границы `line`.
- **`MuiToggleButtonGroup` и `MuiToggleButton`:** вид сегментированного переключателя (фон `track`, выбранный сегмент `paper`).
- **`MuiLinearProgress`:** высота 6, радиус 3, дорожка `track`, заполнение `brand`.
- **`MuiDialog`, `MuiDrawer`, `MuiMenu`, `MuiPopover`:** тень всплывающих слоёв, затемнение `overlay`, радиус `xl` у диалога.
- **`MuiTooltip`, `MuiCheckbox`, `MuiAlert`:** под токены.
- **`MuiCssBaseline`:**
  - сглаживание шрифта и табличные цифры;
  - `text-wrap: balance` у заголовков;
  - стиль кольца фокуса `:focus-visible` для элементов вне MUI.

### 8. Иконки

**Источник.** Пакет `@material-symbols/svg-400`, вариант `rounded`, насыщенность 400. Для активного состояния берётся файл `-fill`.

**Подключение.** SVG импортируются как React-компоненты через `vite-plugin-svgr` (`?react`). Плагин настроен только на суффикс `?react`, так что обычный импорт SVG по-прежнему даёт URL. Типы плагина подключаются в `tsconfig.app.json`.

**Реестр.** В `shared/ui/icon/icons.ts` перечислены только используемые иконки с понятными именами: `shipping` → `local_shipping`, `shelves`, `skillet` и т.д. Новая иконка добавляется в реестр одной строкой.

**Компонент `Icon`:**
- рендерит иконку через `SvgIcon` MUI с `inheritViewBox`, потому что у файлов `viewBox="0 -960 960 960"`;
- пропсы: `name`, `filled`, `size` (`sm` 16, `md` 20, `lg` 24) и `label`;
- без `label` иконка декоративная и получает `aria-hidden`;
- с `label` получает `role="img"` и `aria-label`.

Отвергнуто:
- **variable-шрифт Material Symbols.** Несколько мегабайт ради плавной оси насыщенности, которая нам не нужна.
- **прямые импорты SVG в компонентах.** Набор расползается, и не видно, какие иконки уже используются.
- **`@mui/icons-material`.** Это старый набор Material Icons, без rounded в нужном виде. Пакет удаляется.

### 9. Тема: режим, хранение, отсутствие вспышки

**Провайдер.** `ThemeProvider` получает `defaultMode="system"` и `modeStorageKey="goden-color-mode"`. Пока пользователь не выбрал тему сам, MUI следует `prefers-color-scheme`, в том числе при смене системной темы на лету. Если браузер системную тему не сообщает, `prefers-color-scheme` не совпадает с `dark`, и остаётся светлая.

**Переключение.** `ModeToggle` вызывает `setMode('light' | 'dark')` из `useColorScheme`. Явный выбор сохраняется под тем же ключом и с этого момента имеет приоритет над системной темой.

**Допущение.** Переключатель двухпозиционный: светлая или тёмная. Отдельного пункта «как в системе», чтобы снова следовать системе после явного выбора, в этом изменении нет. Если понадобится, добавится третьим вариантом без изменения остального поведения.

**Против вспышки.** Inline-скрипт в `<head>` файла `index.html` до загрузки бандла:
- читает тот же ключ из `localStorage`;
- если там `light` или `dark`, берёт сохранённое значение;
- иначе берёт `dark`, когда `matchMedia('(prefers-color-scheme: dark)')` совпадает, и `light` в остальных случаях;
- ставит класс `light` или `dark` на `<html>` и выставляет `color-scheme`;
- обёрнут в `try/catch`, при любой ошибке остаётся светлая тема.

**Ключ хранения и логика выбора** продублированы в скрипте и в MUI. Чтобы они не разошлись, два теста:
- тест читает `index.html` и проверяет, что в скрипте тот же ключ и тот же формат классов, что в `theme.ts`;
- тест выполняет скрипт в jsdom с подменёнными `localStorage` и `matchMedia` и проверяет класс на `<html>` для четырёх случаев: сохранён `dark`; сохранён `light` при тёмной системе; ничего не сохранено при тёмной системе; `matchMedia` недоступен.

Отвергнуто:
- **`InitColorSchemeScript` из React.** В SPA он выполнится только после загрузки бандла, то есть слишком поздно.
- **Всегда светлая по умолчанию.** Пересмотрено по решению команды: учитываем системную тему пользователя.

### 10. Оболочка и роуты

**Layout.** `AppShell` в `app/layouts/app-shell` заменяет текущий `root-layout`:
- навигация слева: от 1200px боковая панель 232px с подписями, уже — рельс 76px;
- контент справа;
- devtools остаются.

**Конфигурация навигации** — массив `{ to, label, icon }` в `app/layouts/app-shell/nav-items.ts`. Активный пункт определяется через `Link` TanStack Router (`activeProps`): `aria-current="page"`, фон `paper` с рамкой, залитая иконка цвета `brandInk`.

**Роуты разделов:**
- `/` — «Сводка», существующая `pages/dashboard`;
- `/stock`, `/deliveries`, `/orders`, `/kitchen`, `/stop-list`, `/analytics` — общая страница `pages/section-stub` с названием раздела и пустым состоянием «Раздел в разработке».

Страница не найдено задаётся через `notFoundComponent` корневого роута на `EmptyState`.

**Витрина `/dev/ui`:**
- роут `app/routes/dev.ui.tsx`;
- в `beforeLoad` при `import.meta.env.PROD` бросается `notFound()`;
- компонент выбирается выражением `import.meta.env.DEV ? DevUiPage : () => null`;
- в production условие статически ложно, и сборщик выкидывает `pages/dev-ui` из бандла. Проверяется задачей: в собранном бандле нет строк витрины.

**Логотип.** `shared/ui/logo`: плитка-заглушка и слово «Goden». Знак заменим, когда дизайнер пришлёт финальный SVG.

### 11. Индикатор связи

Компоненты в `shared/ui/connection-status`:
- `ConnectionIndicator` — тихая строка «в сети · обновлено HH:MM»;
- `ConnectionBanner` — плашка `warnTint` с иконкой, текстом и кнопкой «Повторить».

Оба получают состояние пропсом:

```
type ConnectionState =
  | { status: 'online'; updatedAt: Date }
  | { status: 'offline' | 'reconnecting'; dataAt: Date; onRetry: () => void };
```

`AppShell` принимает необязательный `connection?: ConnectionState`. Сейчас его никто не передаёт, поэтому ничего не отображается (сценарий спеки «Источник состояния не подключён»). Изменение про SSE добавит источник и передаст состояние в оболочку, компоненты при этом менять не придётся.

Объявления для программ чтения с экрана идут через `role="status"` (вежливо). Плашка при потере связи использует `role="alert"`.

### 12. Поле количества

`QuantityField` собран по рецепту MUI v9 «spinner field» на `NumberField` из `@base-ui/react`:
- кнопки −/+ по бокам;
- `locale="ru-RU"`, поэтому десятичная запятая работает и при вводе, и при отображении;
- пропсы: `label`, `value`, `onValueChange`, `min` (по умолчанию 0), `step`, `unit` (выводится в подписи);
- видимая подпись над полем;
- размеры по разделу 6.

Отвергнуто:
- **своё поле на `InputBase` с ручным разбором чисел.** Base UI даёт клавиатуру, ARIA, ограничения и локаль из коробки.

### 13. Диалог подтверждения

`ConfirmDialog` собран на `Dialog` MUI:
- заголовок, тело (слот для итогов), кнопки «Отмена» и основное действие;
- `role="alertdialog"`;
- Escape и клик по фону закрывают диалог без действия.

Скрываемое предупреждение задаётся пропсом `dismissibleNotice={{ id, text }}`:
- галочка «Больше не показывать это предупреждение» сохраняет `goden.notice.<id>` в `localStorage` через `shared/lib/storage`;
- скрывается только блок предупреждения, сам диалог показывается всегда (по спеке).

## Risks / Trade-offs

- **Граница полей темнее, чем на макетах** → поля визуально тяжелее. Взято минимальное значение, которое проходит 3:1. Если будет смотреться грубо, утолщать не будем, а сменим оттенок в пределах порога.
- **`(pointer: coarse)` на гибридных ноутбуках с сенсорным экраном** даёт компактные элементы, если основной ввод — мышь. Для них это ожидаемое поведение.
- **Inline-скрипт темы дублирует логику MUI** (ключ, классы) → тест сверки из раздела 9.
- **Плагин SVG и путь `?react`** нужно согласовать с TypeScript и ESLint → типы плагина подключаются в `tsconfig.app.json`, проверка через `pnpm typecheck`.
- **Base UI — новая зависимость с собственным API** → используется только внутри `QuantityField`, наружу торчит наш интерфейс.
- **Переопределения MUI могут сломаться при обновлении MUI** → все в одном файле `components.ts`, витрина показывает каждый компонент для быстрой проверки.
