# Proposal

## Why

Каталог доступен через API только наполовину: продукты можно создать и прочитать, а блюда и рецептуры - нет. Без них через API нельзя собрать меню, а значит нельзя оформить заказ, показать стоп-лист и запустить генератор. Это оставшаяся часть задачи A2.1 из [backend/plan.md](../../../backend/plan.md).

## What Changes

- В контракт `backend/api/openapi.yaml` добавляются четыре операции: создание блюда, список блюд с рецептурами, блюдо по идентификатору, замена рецептуры блюда.
- Модуль `catalog` получает HTTP-обработчики этих операций поверх готовых методов `CreateDish`, `ChangeRecipe`, `Dish`, `Dishes`.
- Список блюд становится постраничным, как список продуктов.
- Правила каталога и общие правила API не меняются: используются существующие команды, формат ошибок, пагинация и идемпотентность.
- В `backend/plan.md` задача A2.1 отмечается выполненной.

Вне изменения: редактирование и удаление блюд (событий для этого нет), эндпоинты поставок, заказов и склада (A3.2, A4.1, A5.1), авторизация (A7).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `catalog`: добавляется требование доступности блюд и рецептур через HTTP API и постраничного чтения списка блюд.

## Impact

- **Код:** `backend/api/openapi.yaml`, перегенерированный `backend/internal/api/oas`, `backend/internal/catalog/http.go`, `service.go`, `queries.sql` и `db/`.
- **Документы:** `backend/plan.md` - статус A2.1.
- **Разработчик B:** не затрагивается.
- **Frontend:** получает эндпоинты для экрана блюд и рецептур и для экрана повара в части состава блюд.
