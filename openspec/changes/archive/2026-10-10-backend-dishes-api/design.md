# Design

## Context

Мотивация и границы - в proposal.md. Изменение повторяет на блюдах то, что уже сделано для продуктов в `backend-api-skeleton`:

- контракт `api/openapi.yaml` с общими параметрами `Limit`, `Offset`, `IdempotencyKey` и ответом `Error`;
- `catalog/http.go` с обработчиками продуктов как образец;
- `api.Handler` уже встраивает `*catalog.HTTP`, поэтому новые методы этого типа становятся операциями без правок слоя API;
- `problemFor` уже знает `*catalog.ValidationError`, `*catalog.UnknownProductError`, `catalog.ErrNotFound`, `catalog.ErrNameTaken`;
- `catalog.Service.Dishes` возвращает все блюда без пагинации и читает ингредиенты всех блюд одним запросом.

## Goals / Non-Goals

**Goals:**

- Новые эндпоинты не вводят ни одного нового правила API: только операции и схемы.

**Non-Goals:**

- Частичное изменение рецептуры. Рецептура заменяется целиком: так устроены команда `ChangeRecipe` и событие `RecipeChanged`.

## Decisions

### 1. Операции

| Операция | Метод и путь | Ответ |
| --- | --- | --- |
| `createDish` | `POST /dishes` | 201, `Dish` |
| `listDishes` | `GET /dishes` | 200, `DishPage` |
| `getDish` | `GET /dishes/{dishId}` | 200, `Dish` |
| `changeRecipe` | `PUT /dishes/{dishId}/recipe` | 200, `Dish` |

Рецептура - вложенный ресурс блюда, а замена целиком - семантика `PUT`. Повторный `PUT` с тем же телом без ключа идемпотентности создаст второе событие `RecipeChanged` с тем же составом: состояние не изменится, но история вырастет. От этого защищает `Idempotency-Key`, который операция принимает, как и `POST`.

Схемы: `NewDish` (`name`), `Dish` (`id`, `name`, `ingredients`), `Ingredient` (`product_id`, `quantity` с `minimum: 1`), `Recipe` (`ingredients` с `minItems: 1`), `DishPage` (`items`, `total`).

Ограничения `minItems` и `minimum` в контракте не зависят от нормализации данных, поэтому по принятому правилу живут в схеме и дают 400. Повтор продукта и существование продукта схема выразить не может: их проверяет домен и возвращает 422.

### 2. Пагинация списка блюд

`Dishes` получает параметр `Page` и возвращает страницу и общее число, как `Products`. Ингредиенты читаются только для блюд страницы: запрос `ListAllIngredients` заменяется запросом по набору идентификаторов блюд. Прежний запрос больше нигде не используется и удаляется.

### 3. Обработчики

Четыре метода в `catalog/http.go` и две функции преобразования между типами модуля и сгенерированными типами. Автор берётся из `httpx.Actor`, ключ идемпотентности - из параметров операции.

## Risks / Trade-offs

- [Изменение сигнатуры `Dishes`] → затрагивает только тесты каталога: других потребителей у списка блюд нет, заказы читают блюда по одному через `DishIn`.
- [Повторный `PUT` рецептуры без ключа плодит одинаковые события] → см. решение 1; состояние остаётся верным.
