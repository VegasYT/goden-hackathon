# Design

## Context

Grafana уже загружает `infra/grafana/dashboards/goden-backend.json` как домашний дашборд с UID `goden-backend`; его панели явно используют Prometheus. Loki provisioned с UID `loki`. Метки Loki низкокардинальны: `environment`, `compose_project`, `compose_service`, `stream`; прикладные поля разбираются из JSON на этапе запроса.

## Goals / Non-Goals

**Goals:**

- Добавить воспроизводимую секцию логов в существующий дашборд без изменения его UID, URL и панелей метрик.
- Разделить просмотр исходного контейнерного вывода и фильтрацию структурированных backend-логов.
- Использовать только существующий datasource и стабильные labels.

**Non-Goals:**

- Не создавать второй дашборд и не менять запросы существующих панелей метрик.
- Не сохранять пользовательские фильтры и не добавлять Grafana alerts.

## Decisions

### Расширение существующего provisioned JSON

Изменить `infra/grafana/dashboards/goden-backend.json`, сохранив UID `goden-backend`, заголовок и существующие панели. Логовые панели добавить в отдельную строку после метрик; каждая новая панель явно использует datasource UID `loki`, существующие продолжают использовать `prometheus`. Отдельный дашборд был рассмотрен, но отклонён по решению пользователя: метрики и логи должны находиться на одном экране.

### Переменные на основе labels и явный фильтр уровня

Переменная окружения получает значения label `environment`, а список сервисов зависит от выбранного окружения через `compose_service`. Сервис и уровень поддерживают All/multi-select; All разворачивается в regex. `correlation_id` — textbox со значением по умолчанию `.*`; его regex передаётся через raw-format Grafana в raw-строку LogQL, чтобы обратные слэши не стали недопустимыми escape-последовательностями. Уровни задаются фиксированным списком `DEBUG`, `INFO`, `WARN`, `ERROR`, потому что они являются полем JSON, а не label Loki.

### Раздельные панели raw и JSON

Общая logs-панель использует только selector по окружению и сервису и поэтому сохраняет JSON и обычный текст. Структурированная logs-панель применяет `| json`, отбрасывает ошибки парсинга и фильтрует `level` и `correlation_id`. Агрегат ошибок использует `count_over_time` по выбранному периоду и группировку по `compose_service`; запрос выполняется как instant, чтобы показывать итог за период.

### Проверка через API, а не ручной импорт

После перезапуска Grafana сохранность UID, существующих Prometheus-панелей и появление Loki-панелей проверяются через Grafana API. LogQL новых панелей выполняется через datasource proxy на тестовых JSON- и текстовых записях; это проверяет provisioning и семантику фильтров без сохранения UI-изменений.

## Risks / Trade-offs

- [Локально backend запущен с хоста и отсутствует в Loki] → документация явно указывает границу; дашборд всё равно показывает контейнерные сервисы.
- [Общий дашборд становится длиннее] → логовые панели помещаются в отдельную строку после метрик и не меняют их сетку.
- [Структурированная панель скрывает обычный текст] → исходные строки остаются в отдельной общей ленте.
- [Широкий период создаёт дорогой `count_over_time`] → дашборд по умолчанию открывает короткий период, а агрегат ограничивается выбранным диапазоном.
- [Спецсимволы в `correlation_id`] → передавать значение как regex в raw-строке LogQL; оператор не должен вводить обратную кавычку.

## Migration Plan

Обновить существующий JSON и пересоздать Grafana: provider перезагрузит тот же UID без изменения сохранённых данных. Для отката вернуть предыдущую версию `goden-backend.json` и пересоздать Grafana; Loki, Promtail и сохранённые логи не затрагиваются.
