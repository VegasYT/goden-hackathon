# Proposal

## Why

Вся логика записи потока A готова, но снаружи недоступна: в репозитории нет ни контракта API, ни HTTP-сервера, ни исполняемых процессов, кроме `cmd/migrate`. Систему нельзя запустить и проверить руками, frontend не может начать работу с настоящим API, а задачи A2.1, A6, A7 и A8 заблокированы. Задачи 0.5 и 0.6 этапа 0 в плане закреплены за разработчиком B, но он к ним не приступал; по решению команды их забирает разработчик A.

## What Changes

- Появляется контракт `backend/api/openapi.yaml`: общие соглашения API и первые настоящие эндпоинты - создание продукта, список продуктов, продукт по идентификатору.
- Фиксируются соглашения для всех будущих эндпоинтов: ошибки в формате `application/problem+json` (RFC 9457) с перечнем некорректных полей, пагинация списков, заголовок ключа идемпотентности, сквозной correlation ID.
- Проверяется и закрепляется выбор генератора: ogen на первом эндпоинте с телом запроса, пагинацией и ошибками. Результат записывается в `backend/AGENTS.md`.
- Появляется `cmd/api`: HTTP-сервер с эндпоинтами API, `/healthz`, `/readyz`, логированием запросов и корректным завершением по сигналу.
- Появляется `cmd/worker`: каркас процесса фоновых задач с теми же health-эндпоинтами и корректным завершением. Самих задач в нём пока нет: их добавляет разработчик B.
- Модуль `catalog` получает HTTP-обработчики продуктов и постраничное чтение списка.
- Появляется тестовая обвязка API: сервер поднимается в тесте на настоящей базе, запросы идут через сгенерированный клиент.
- `backend/plan.md`: задачи 0.5 и 0.6 переходят к разработчику A.

До задачи A7 авторизации нет: все запросы выполняются от имени фиксированного пользователя разработки. Это временное состояние, сервер пишет о нём предупреждение при старте.

Вне изменения: `docker compose` (задача 0.4), остальные эндпоинты каталога (A2.1) и эндпоинты поставок, заказов и склада, Keycloak (A7), метрики (A8), SSE, Kafka, Redis, содержательные задачи worker.

## Capabilities

### New Capabilities

- `http-api`: общие правила HTTP API - формат ошибок, пагинация, идемпотентность запросов на запись, correlation ID, health-эндпоинты.

### Modified Capabilities

- `catalog`: добавляется требование доступности продуктов через HTTP API и постраничного чтения списка продуктов.
- `backend-platform`: добавляется требование к жизненному циклу процессов - запуск, готовность, корректное завершение.

## Impact

- **Код:** `backend/api/openapi.yaml`, `backend/ogen.yml`; сгенерированный пакет `backend/internal/api/oas`; `backend/internal/api` - сборка обработчиков и преобразование ошибок; `backend/internal/platform/httpx` - middleware, запуск сервера, health; `backend/internal/catalog/http.go`; `backend/cmd/api`, `backend/cmd/worker`.
- **Зависимости:** библиотека времени выполнения ogen и её зависимости.
- **Документы:** `backend/AGENTS.md` - итог проверки ogen, команды генерации и запуска, структура слоя API; `backend/plan.md` - владелец задач 0.5 и 0.6.
- **Разработчик B:** получает готовые `cmd/api` и `cmd/worker`, в которые добавляет свои эндпоинты чтения, SSE и фоновые задачи. Задачи 0.5 и 0.6 ему делать не нужно; за ним остаётся 0.4.
- **Frontend:** получает первый настоящий контракт и работающие эндпоинты продуктов; типы можно генерировать из `backend/api/openapi.yaml`.
