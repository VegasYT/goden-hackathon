# Spec Delta

## ADDED Requirements

### Requirement: Жизненный цикл процессов
Система SHALL предоставлять два серверных процесса: процесс API, обслуживающий HTTP-запросы, и процесс фоновых задач. Каждый процесс при запуске SHALL загрузить конфигурацию, подключиться к базе данных и только после этого сообщать о готовности. При получении сигнала завершения процесс SHALL перестать принимать новую работу, дождаться завершения текущей в пределах заданного времени и завершиться с нулевым кодом. При ошибке запуска процесс SHALL завершиться с ненулевым кодом и сообщением о причине.

#### Scenario: Запуск процесса API
- **WHEN** процесс API запускают с корректной конфигурацией и доступной базой данных
- **THEN** он начинает принимать запросы и отвечает 200 на `/readyz`

#### Scenario: Корректное завершение
- **WHEN** работающему процессу отправляют сигнал завершения во время обработки запроса
- **THEN** запрос завершается штатно, новые соединения не принимаются, процесс завершается с кодом 0

#### Scenario: База данных недоступна при запуске
- **WHEN** процесс запускают с адресом недоступной базы данных
- **THEN** процесс завершается с ненулевым кодом и сообщением об ошибке подключения

#### Scenario: Запуск процесса фоновых задач
- **WHEN** процесс фоновых задач запускают с корректной конфигурацией
- **THEN** он отвечает 200 на `/readyz` и завершается с кодом 0 по сигналу завершения
