## Context

Состояние поставки - свёртка событий её потока (`foldDelivery`); список - проекция, которая хранит ту же свёртку целиком. События приёмки, карантина и исправления уже несут своё время и автора в полезной нагрузке, но не несут точку. Автор (`eventstore.Actor`) - тип и логин.

## Decisions

- **Новые поля поставки считает свёртка**, а не обработчик: время открытия карантина, решения по карантину, исходное распределение и время исправления берутся из событий потока. Список получает их через новую версию проекции. Решение по карантину - одна команда и до двух событий с одним временем: свёртка склеивает их в одну запись по времени решения.
- **Остаток по позиции и категория продукта подставляются при ответе**, как уже подставляются название и единица: остаток меняется заказами, а не событиями поставки, и в свёртке был бы устаревшим. В записях истории это тоже текущий остаток, а не остаток на момент события.
- **Имя автора подставляется при ответе, в события не записывается.** Таблица событий не допускает изменения и удаления: записанное имя осталось бы там навсегда и не следовало бы за сменой имени в Keycloak. В событии хранится логин, а таблица пользователей ведётся по идентификатору Keycloak, поэтому в неё добавляется логин; он обновляется вместе с почтой и именем при запросе профиля. Следствие: имя получают и события, записанные раньше.
- **Точка добавляется в четыре события потока поставки без новой версии схемы.** Поле нужно потоку обновлений для адресации. У прежних событий оно пустое: сигнал читает только новые события, свёртка берёт точку из регистрации. Так же точка добавлялась в события склада.
- **Категория `deliveries` не входит в сигнал складских событий.** Иначе каждый заказ заставлял бы перечитывать поставки. Следствие: остаток по позиции клиент обновляет по категории `stock`.
- **Причины - перечисление только в запросе**, проверяет разбор запроса по контракту. В событиях и ответах причина остаётся строкой: на стенде уже есть поставки со свободным текстом, закрытое перечисление в событии сделало бы их нечитаемыми.
- **Число позиций в открытом карантине - столбец проекции**, а не разбор `jsonb` при каждом запросе сводки.
- **Код и предел ошибки поля** - необязательный метод `FieldDetail` у ошибки валидации модуля; слой API читает его, не зная типов модулей, как уже читает `InvalidField`.

## Risks / Trade-offs

- Сигнал `deliveries` может прийти раньше, чем проекция списка применит событие (обе читают события независимо, разрыв - доли секунды). Чтение поставки по идентификатору не отстаёт; список и сводка могут на мгновение показать прежнее. Сервер уже задерживает сигнал на четверть секунды для склейки, это закрывает большинство случаев, но не гарантирует.
- Логин известен системе только после запроса профиля с новой версией: до этого у автора в ответах только логин. Два пользователя с одним логином невозможны в одном realm Keycloak.
- После выкладки список поставок пуст, пока проекция перестраивается.
