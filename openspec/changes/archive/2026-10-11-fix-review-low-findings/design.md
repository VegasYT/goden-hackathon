## Decisions

**Завышенный заказ генератора - на предел порций API (10000).** Смысл такого заказа - получить отказ и показать работу проверки остатков. Прежние 200-500 порций при большом остатке принимались и определяли весь расход стенда. Вычислить "остаток плюс один" генератор не может: меню доступно по праву `kitchen.view`, которого у его учётной записи нет, и расширять права ради этого не стоит. Вывод из кода и ADR-006.

**Нулевой символ ищется в тексте тела запроса.** Точная проверка требует разбора JSON до обработчика. Поиск по тексту отклонит и строку, в которой перед `u0000` стоит экранированная обратная косая черта, то есть текст, а не символ; в данных ресторана такого не бывает. Отмечено комментарием в коде.

**Разрыв соединения - статус 499.** Стандартного статуса для этого нет; 499 принят у обратных прокси. Клиент ответ не увидит, статус нужен метрикам и журналу.

**Автор входит в отпечаток запроса, а не в ключ таблицы.** Изменение первичного ключа `command_results` потребовало бы миграции и разрешило бы двум авторам один ключ; отпечаток даёт нужное поведение без неё: чужой ключ отклоняется как повторно использованный. Следствие: отпечатки, сохранённые до выкладки, не совпадут с новыми. Затронуты только повторы запросов, начатых до выкладки.

**Пробелы в списке адресов CORS обрезаются в `cmd/api`.** Библиотека настроек делит значение по запятой без обрезки.

## Risks / Trade-offs

- После выкладки генератор перестанет расходовать склад большими заказами: остатки начнут расти, стоп-лист станет появляться реже → соотношение поставок и заказов настраивается через `PUT /generator`.
- Повтор запроса, начатого до выкладки, получит 422 → окно равно времени выкладки.
