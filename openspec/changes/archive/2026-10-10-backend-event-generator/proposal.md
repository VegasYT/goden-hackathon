# Proposal

## Why

Систему сейчас можно проверить только руками, по одному запросу. Для демо на защите, для нагрузочной проверки корректности (A9) и для разработчика B, которому нужен непрерывный поток событий для проекций, стоп-листа и SSE, требуется источник правдоподобной активности ресторана. В кейсе генератор событий прямо назван среди дополнительных пунктов, а ADR-012 задаёт, как он должен работать. Это задача A6 из [backend/plan.md](../../../backend/plan.md).

## What Changes

- Появляется процесс `cmd/generator`: он эмулирует работу ресторана через публичный REST API, как внешний клиент. К базе данных и Event Store он не обращается.
- Генератор создаёт поставки по полному пути из ADR-012: регистрация, приёмка с отбраковкой просроченных позиций и карантином части позиций, решение по своему карантину.
- Генератор оформляет заказы; часть из них намеренно превышает остатки, чтобы появлялись отказы и срабатывал стоп-лист.
- Продукты, блюда и сроки хранения генератор берёт из каталога системы. Если каталог пуст, он один раз наполняет его демонстрационным набором.
- В API появляются настройки генератора: запущен или остановлен, интенсивность поставок и заказов. Генератор читает их через тот же API и подстраивается без перезапуска.
- Появляется модуль `generator`: хранение настроек, HTTP-обработчики настроек и логика симуляции.

**Отступление от ADR-012:** сервисная учётная запись Keycloak и право `generator.manage` в это изменение не входят. Авторизации в системе пока нет (задача A7), а Keycloak появится только с окружением из задачи 0.4. Генератор ходит в API так же, как любой клиент сейчас: от имени пользователя разработки. Учётная запись и права добавляются в A7 без изменения логики генератора. `backend/plan.md` это фиксирует.

Вне изменения также: ускоренное время и короткие сроки годности для демо (команда отказалась от них при обсуждении плана), статистика работы генератора в API, нагрузочный тест под генератором (A9).

## Capabilities

### New Capabilities

- `event-generator`: генератор событий - настройки через API, сценарии поставок и заказов, наполнение пустого каталога, работа только через публичный API.

### Modified Capabilities

Нет.

## Impact

- **Код:** новый модуль `backend/internal/generator/`; `backend/cmd/generator/`; операции настроек в `backend/api/openapi.yaml` и перегенерированный `backend/internal/api/oas`; сборка в `backend/internal/api/api.go`; миграция таблицы настроек; правило `depguard` и запись в `sqlc.yaml` для нового модуля.
- **Документы:** `backend/AGENTS.md` - команда запуска генератора и переменные окружения; `backend/plan.md` - статус A6 и перенос учётной записи Keycloak в A7.
- **Разработчик B:** получает поток настоящих событий всех типов для проекций и интеграций; в контракте появляется раздел `generator`.
- **Frontend:** получает эндпоинты для экрана управления генератором.
- **Infra:** третий процесс backend для будущего `docker compose`.
