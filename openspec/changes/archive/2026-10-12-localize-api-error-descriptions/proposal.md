# Proposal

## Why

API возвращает человекочитаемые описания ошибок на английском, хотя пользовательский интерфейс системы русскоязычный. Клиенты должны получать понятные русские сообщения без изменения машинных кодов ошибок и HTTP-статусов.

## What Changes

- Все человекочитаемые поля ответа `application/problem+json` (`title`, `detail`, `errors[].message`) возвращаются на русском языке.
- Русификация охватывает ошибки контракта, авторизации, валидации, ссылок на неизвестные объекты, конфликтов и внутренних сбоев.
- Значения `type`, имена полей, HTTP-статусы и структура ответа сохраняются для обратной совместимости клиентов.
- Внутренние технические подробности по-прежнему не раскрываются в ответах.

Вне изменения: локализация логов и доменных ошибок вне HTTP-ответа, выбор языка по запросу клиента, изменение OpenAPI-схемы или бизнес-правил.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `http-api`: формат ошибок дополняется обязательной русской локализацией человекочитаемых описаний при сохранении машинных кодов.

## Impact

- `backend/internal/api` и `backend/internal/platform/httpx`: формирование ошибок обработчиков, middleware и ошибок разбора запроса.
- Тесты backend на содержимое `Problem`.
- Публичное поведение API для frontend и внешних клиентов меняется только в текстовых описаниях; `backend/api/openapi.yaml` и сгенерированные типы не меняются.
