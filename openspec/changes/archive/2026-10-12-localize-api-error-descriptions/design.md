# Design

## Context

API формирует `Problem` в двух местах: `internal/api` преобразует ошибки операций и ogen, а `internal/platform/httpx` отвечает за ошибки тела запроса и восстановление после паники. Сейчас часть ответов берёт `err.Error()` из домена или библиотеки, поэтому английский текст может попасть в `title`, `detail` и `errors[].message`.

## Goals / Non-Goals

**Goals:**

- Гарантировать русский текст во всех человекочитаемых полях HTTP-ошибки.
- Сохранить текущие `type`, статусы, поля и защиту от утечки внутренних подробностей.

**Non-Goals:**

- Не менять тексты доменных ошибок, логов и ошибок сторонних библиотек.
- Не добавлять выбор локали и инфраструктуру переводов для нескольких языков.

## Decisions

### Локализация на границе HTTP

`problemFor` будет собирать русские описания по типу или sentinel-ошибке, не передавая клиенту исходный `err.Error()`. Для типизированных ошибок с идентификатором русское описание сохранит этот идентификатор; для прав доступа — машинное имя требуемого права.

Решение выведено из существующей архитектуры: `problemFor` уже является единственным преобразователем доменных ошибок в HTTP. Альтернатива — перевести ошибки во всех доменах — затронула бы логи и внутренние контракты вне задачи.

### Валидация с безопасным запасным сообщением

Сообщения `InvalidField` локализуются централизованно по известным шаблонам, включая шаблоны с идентификаторами и числовыми пределами. Для неизвестного сообщения API вернёт общее русское описание некорректного значения, а исходный английский текст останется только во внутренней ошибке.

Альтернатива — считать любой новый английский текст допустимым — не гарантирует требование русской локализации после добавления новых доменных проверок.

### Ошибки контракта без текста ogen

Для ошибок разбора параметров и тела API возвращает общее русское пояснение вместо `err.Error()`: детали ogen являются англоязычными, нестабильными между версиями и не нужны для машинной обработки. Имя проблемного поля остаётся доступно там, где его уже предоставляет доменная валидация.

### Прямые ответы middleware

Статические `Problem` в маршрутизации и `httpx` переводятся на русский. Машинные коды не переводятся и не меняются.

## Risks / Trade-offs

- [Общее сообщение ошибки контракта менее подробно, чем текст ogen] → клиент по-прежнему получает стабильные `type` и статус; конкретные доменные ошибки сохраняют поле и локализованное пояснение.
- [Новый шаблон доменной валидации может не иметь отдельного перевода] → безопасный русский fallback исключает возврат английского текста; тест покрывает fallback.
